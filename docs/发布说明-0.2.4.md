# 0.2.4 测试版：副屏输入、截图新鲜度与沙箱可执行性

本版尚未发布，用于下一次测试版构建；基线为 `v0.2.3-mobile-323`。

## 改动

- 副屏动作新增受控 `long_press`、`keyevent` 和可打印 ASCII `text`，两端都执行白名单、坐标、时长和长度校验；中文和 emoji 继续使用分享 Intent 或设备输入法。
- 副屏截图返回目标包名、`frameAtElapsedMs` 和 `frameReused`，帮助 AI 区分缓存帧与新帧；静止页面仍可能复用缓存，不承诺高帧率流。
- **修复沙箱内命令与沙箱内 PTY 全部失败**：PRoot 会把受限进程的 `execve` 改写成对 `PROOT_LOADER` 的 `execve`，而那份 loader 原先落在 Landlock 授权根（运行时根）之外，受限执行因此被内核拒绝（`landlock-run: exec failed: Permission denied`，退出码 125）；`--probe` 不执行程序所以照旧通过。现在 loader 以**实体文件**落进运行时根内的 `root/.dsh-mobile/dsh-runner/loader`（符号链接无效：Landlock 按路径最终指向的对象判定），每次启动前与 APK 内的文件比对，不一致就重写；PRoot 本体仍留在应用私有目录。
- 自检新增结论码 `EXEC_LAUNCHER_DENIED`：把「受限执行被内核拒绝」与「其它启动器级失败（`EXEC_LAUNCHER_FAILED`）」分开，下次不必再靠上机复现才能知道是权限被判否。
- 文档加入 HONOR AAP-AN00 / Android 17 真机回执，明确记录硬链接、C 编译器、make、白帧和中文输入限制。

## 未解决的设备限制

- 硬链接被拒绝属于该设备的 PRoot/内核策略限制；应用不会把它伪报为已修复。
- DSH 副屏预览页前台时可能出现白帧；真实第三方应用、小窗互切、长期后台和锁屏恢复仍需继续验证。
- 目标应用副屏仍没有专用无障碍树；中文文本和剪贴板是否可用取决于设备与目标应用。

## 验证

- Kotlin JVM 单测 64 类 / 505 用例（含新增的 `RuntimeLauncherFilesTest`、`RuntimeFilesTest` 内容比对、`RuntimeSelfCheckPolicyTest` 新码）、`lintRelease` 0 Error。
- 前端：`vitest run`、`npx tsc -b`、`eslint . --max-warnings 0` 通过；脚本层 `node --test scripts/*.test.mjs` 通过。
- 真机复现（HONOR AAP-AN00，Android 17，shell uid 下同一套设备二进制）：loader 在授权根外时 `--ro /` / 自检原样 / 沙箱内 shell 三条全部退出码 125，把 loader 以实体文件放进根内后三条全部退出码 0；根内符号链接仍为 125。
- 升级后的正式包在应用 uid 上的复测仍需真机完成（本条不得当作已验证）。
