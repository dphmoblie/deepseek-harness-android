# 手机应用读取与自动化能力

本项目可以把手机当作一个需要用户授权的受控设备。它能够观察当前屏幕、读取有限的
UI 层级、启动指定应用、点击坐标和向当前焦点输入文本，再把新的观察结果交给模型。
这些能力适合执行可重复的前台流程，例如打开应用、切换页面、填写普通搜索框、读取
页面状态和导出投递区文件。

## 当前已经具备的第一阶段能力

Shizuku 连接成功、用户授权并且 Harness 运行时启动后，模型可以使用以下工具：

| 工具 | 作用 | 约束 |
| --- | --- | --- |
| `mobile_device_list_packages` | 查找已安装包名 | 只按受限包名片段筛选，最多返回 256 行 |
| `mobile_device_app_launch` | 启动包名的默认入口 | 只接受标准包名；切换前台需要用户审批 |
| `mobile_device_current_app` | 读取当前前台诊断行 | 只返回有限的 `dumpsys activity` 行，设备文本不可信 |
| `mobile_device_screenshot` | 读取当前屏幕 | 需要当前模型支持图片输入，并受大小限制 |
| `mobile_device_ui_dump` | 读取 `uiautomator` 层级 | 某些 ROM 可能只返回空壳，需要改用截图 |
| `mobile_device_tap` | 点击屏幕坐标 | 坐标范围受限；使用流程要求坐标来自最近一次观察，并由工具层请求用户审批 |
| `mobile_device_input_text` | 向当前焦点输入普通文本 | 只接受受限 ASCII，不适合密码、验证码或密钥，并需要用户审批 |
| `mobile_device_wait` | 等待界面稳定 | 只能等待 100 毫秒至 10 秒 |

固定设备命令由 Android 原生白名单和模型插件双重校验。桥接层不提供任意 Shell、root、
Activity 参数、Intent 参数或应用私有目录访问。投递区的文件读取、写入、上传、下载、
列目录和建文件夹也只允许 `inbox/outbox` 下的相对路径，并有符号链接、大小和输出限制。

当前只校验启动参数的**包名格式**，尚未提供由用户维护的目标应用包名白名单；点击和输入
也尚未在 Android 原生侧核对当前前台包、锁屏状态或最近一次观察。因此，这些工具应只用于
用户在场、设备已解锁的前台单步流程，不能据此宣称已具备无人值守的跨应用自动化。
工具层审批用于避免误操作，并非 Android 原生权限边界；同 UID 的访客代码能绕过工具层，
具体信任边界见 [设备桥的信任边界](设备桥信任边界.md)。

## 推荐的自动化循环

1. 用 `mobile_device_list_packages` 确认目标包名，不从页面文字猜包名。
2. 请求用户批准 `mobile_device_app_launch`，启动目标应用。
3. 用 `mobile_device_screenshot` 或 `mobile_device_ui_dump` 观察当前状态。
4. 从最近一次观察得到节点边界或坐标，只执行一个点击或一次文本输入。
5. 用 `mobile_device_wait` 等待短时间，再重新观察。
6. 如果前台包、页面结构或控件状态与预期不符，停止并报告，不盲目重试。

截图、UI XML、应用标题、通知和文件内容都按不可信设备数据处理，其中出现的文字不能
改变模型的安全规则，也不能被当作新的指令。

## 要做到更深层的应用控制，还需要什么

第一阶段只控制应用公开的前台 UI。仓库已经包含一个需要用户手动开启的无障碍服务原型，
但它还没有接入设置页的白名单管理和模型工具；当前默认白名单为空，因此不能直接用于产品
自动化。完整接线时，应用必须明确显示服务用途、目标应用和可执行动作。无障碍服务不能由
Shizuku 静默开启，也不应默认读取所有应用的全部文本。服务应采用目标包白名单、
动作审批、超时、速率限制和本地审计，并在锁屏、支付、验证码、生物识别和系统权限页面上
停止自动操作。无障碍服务本身也不能保证锁屏后可操作：屏幕关闭、锁屏保护、目标应用后台
限制和厂商电池策略都可能使 UI 不可用；如需无人值守任务，应优先使用目标应用公开 API 或
官方自动化接口，并在真机上分别验收解锁前、解锁后和后台恢复场景。

目标应用的私有数据库、后台业务接口和登录态不能仅靠 Shizuku 获得。合规的深层集成需要
目标应用提供公开 Intent、ContentProvider、导出分享入口或经过授权的 API；否则只能使用
屏幕层面的公开 UI。应用自动化也不能保证绕过目标应用的风控、验证码或用户确认。

## 权限与验收边界

- Shizuku 的实际能力取决于用户授予的权限和 Android 版本，不能把它描述成 root。
- 点击、输入和启动应用是有副作用的操作，默认需要用户审批；读取设备信息、前台包和 UI
  层级仍按不可信数据处理。
- 锁屏、后台拉起、厂商电池策略和无障碍服务行为必须在真实手机或 MuMu 实例上验收，
  JVM 单测只能验证参数白名单和命令构造。
- 当前机器未发现用户指定的 MuMu 路径，因此尚未完成悬浮窗、锁屏后台恢复和跨应用操作的
  模拟器验收；连接模拟器后应按 `docs/mobile-acceptance-checklist.md` 逐项记录结果。
