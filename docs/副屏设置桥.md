# 副屏设置桥

宿主侧（Capacitor 插件 `MobileRuntimePlugin`）为副屏设置页提供的读写接口。设置页可以读改副屏配置、
启停副屏、读取副屏状态；「自适应分辨率 / 屏幕方向」也是在这里真正接到启动路径上。

- 代码位置：`android/app/src/main/java/io/deepseekharness/mobile/MobileRuntimePlugin.kt`（5 个 `@PluginMethod`）、
  `.../virtualscreen/VirtualScreenPreferences.kt`（入参解析与状态合并）、`.../virtualscreen/VirtualScreenSizing.kt`（规格求解）
- 调用方：**只有前端页面（WebView）**。这些方法是 Capacitor 插件方法，`window.Capacitor.Plugins.MobileRuntime.xxx()` 可见。
  AI 工具面走的是另一条路（插件 JS → `callBridge` → `POST /device-command` → `DeviceBridgeServer`），不在本文范围内。

## 一、方法

| 方法 | 入参 | 成功返回 |
| --- | --- | --- |
| `getVirtualScreenSettings()` | 无 | 设置对象（见 §2.1） |
| `setVirtualScreenSettings({previewMode?, autoFollow?, orientation?, adaptive?, widthPx?, heightPx?, densityDpi?})` | 全部可选，只改传了的字段 | 写回后的设置对象（同上） |
| `startVirtualScreen({packageName, adaptive?, orientation?, widthPx?, heightPx?, densityDpi?})` | `packageName` 必填，可给包名或完整组件名（`包名/类名`） | `{component, orientation, adaptive, widthPx, heightPx, densityDpi}`（本次会话真正要用的规格） |
| `stopVirtualScreen()` | 无 | 旧显示释放后返回 `{stopping:false, active:false}`；超时或释放失败会拒绝调用 |
| `getVirtualScreenState()` | 无 | 状态对象（见 §2.2） |

返回风格与插件里其它方法一致：成功 `call.resolve(payload)`，失败 `call.reject(message, code)`
（**没有** `{ok:…}` / `{error:…}` 包装）。失败时 `code` 见 §4。

## 二、字段与取值

### 2.1 `getVirtualScreenSettings()` / `setVirtualScreenSettings(...)`

```jsonc
{
  "previewMode": "60fps",   // 档位值，见下
  "autoFollow": "off",      // off | pull_back | promote
  "orientation": "auto",    // auto | portrait | landscape
  "adaptive": false,        // 自适应分辨率
  "widthPx": 0,             // 用户自定义值；0 表示没自定义过
  "heightPx": 0,
  "densityDpi": 0,
  "effective": { "widthPx": 726, "heightPx": 1600, "densityDpi": 320 }, // 下一次启动会真正用到的规格
  "active": false           // 此刻是否已有副屏会话
}
```

`widthPx`/`heightPx`/`densityDpi` 与 `effective` 是两回事：前者是用户的自定义值，后者是按
「请求 → 偏好 → 方向预设」和真实屏幕尺寸算出来的落地规格。**页面不要混着显示。**

`effective` 在没有会话时是**推算值**（下一次启动会用到的规格），不代表此刻已有副屏——所以另有 `active`。

### 2.2 `getVirtualScreenState()`

```jsonc
{
  "active": false,                 // 会话是否活着（停止中为 false）
  "sessionId": "",                 // 没有会话时是空串
  "displayId": -1,                 // 没有会话时是 -1
  "previewMode": "60fps",          // 会话里改过档位就以会话为准（设备端标签 realtime-60fps 会翻回档位值）
  "autoFollow": "off",             // 会话优先，其次偏好
  "orientation": "auto",           // 本次会话真正用的方向
  "adaptive": false,               // 本次会话真正用的自适应开关
  "widthPx": 1080,                 // 优先宿主读回的真实参数，其次会话请求值，最后偏好
  "heightPx": 2340,
  "densityDpi": 440,
  "targetPackage": null,           // 副屏目标应用包名；设备端回的是组件名，这里按 "/" 截断；取不到为 null
  "frameFps": 59.9,                // 设备端实测帧率，读不到为 0
  "displayRefreshRate": 120.0,     // 副屏显示刷新率；**读不到回 0（未知）**，不去猜屏幕标称值
  "virtualForegroundPackage": null,   // 透传设备端字段，取不到为 null（见 §5）
  "virtualForegroundActivity": null,
  "starting": false,               // 设备端会话快照里有就带上（透传）
  "stopping": false,
  "error": "",
  "treeSupported": true
}
```

档位值（`previewMode`）只能是这 10 个，逐字：
`limited`、`15fps`、`30fps`、`60fps`、`90fps`、`120fps`、`144fps`、`165fps`、`185fps`、`240fps`。

## 三、校验规则（写请求与启动请求共用）

- **枚举非法 → 整条拒绝**：`previewMode`/`autoFollow`/`orientation` 任一不在允许列表内，整个请求失败，
  **一个字段都不落盘**（否则页面显示的配置与真正落盘的会是两码事）。
- **类型错误 → 整条拒绝**：`"800"` 这类字符串、非布尔值都拒（不静默夹取，否则用户看不出入参写错了）。
- **数值越界 → 夹取**：正数边长夹到 `200..4096`、dpi 夹到 `120..640`，**不抛异常**。
- **0 与负数 → 清掉自定义尺寸**（写 0）：偏好里 0 的语义就是「没自定义过」，
  0 若被夹成 200，用户就再也回不到自适应/方向预设了。这是对「越界一律夹取」的**一处刻意例外**，页面靠它做「重置尺寸」。
- **字段缺省或 `null` → 这一项不改**（`setVirtualScreenSettings` 因此可以只提交一项）。
- `packageName` 缺失或全空白 → 拒绝；给包名时由系统查启动入口，查不到即失败。

## 四、错误码

| code | 触发 |
| --- | --- |
| `VIRTUAL_SCREEN_INVALID` | 入参非法：枚举/类型错误、缺 `packageName`、组件名校验不过 |
| `VIRTUAL_SCREEN_UNSUPPORTED` | Android 版本低于 10（API 29） |
| `VIRTUAL_SCREEN_BUSY` | 启动时已有副屏会话（先 `stopVirtualScreen()`） |
| `VIRTUAL_SCREEN_LAUNCH_UNRESOLVED` | `packageName` 没有可启动入口（未安装/无 launcher activity） |
| `ACTIVITY_UNAVAILABLE` | 需要页面但当前没有（`openVirtualScreen` 专用，与设置页无关） |
| `RUNTIME_CLOSED` | 本机运行时正在关闭，操作被拒 |
| `INTERNAL_ERROR` | 未预期的异常（兜底） |

## 五、自适应与屏幕方向是怎么接上的

1. `setVirtualScreenSettings` 写偏好；`startVirtualScreen` 可以再带一份**只对本次会话生效**的
   `adaptive`/`orientation`/尺寸（不写回偏好）。
2. 规格求解（`VirtualScreenStart.resolve`）按固定优先级取一个来源：
   **请求自适应 → 请求里的尺寸（三项齐全才算）→ 偏好自适应 → 偏好里的尺寸 → 方向预设**（`auto` 按真实屏幕长边判横竖）。
3. 算出来的规格再进 `VirtualScreenStart.gate`：夹进设备端启动闸门
   （宽 ≤ 1440、高 ≤ 2560、宽 × 高 ≤ 2 073 600、dpi 160..640），超预算按比例缩小（dpi 同缩），**只缩不放**。
   这一步保证规格不会在启动时被设备端抛「副屏尺寸超出范围」。
4. 规格 + `adaptive` + `orientation` 一起写进启动 Intent（`putVirtualScreenStart`），服务侧重新解析一次
   —— **换算只发生在服务侧一次**，页面不需要自己算尺寸。
5. 悬浮小窗的尺寸沿用原逻辑（`VirtualScreenWindow.overlaySize`），随副屏宽高比走。

## 六、未在真机验证的行为（本次改造未使用 adb/真机，手机被占用）

1. **尺寸读数路径**：`getVirtualScreenState()` 的 `widthPx`/`heightPx`/`densityDpi`
   来自宿主对副屏 `Display` 调 `getRealMetrics`，读不到才退到会话请求值。
   “副屏 Display 上的 `getRealMetrics` 返回的是副屏而非主屏参数”这一点**未在真机验证**。
2. **`displayRefreshRate`**：读不到时回 `0` 表示未知；真机上是否总能读到也未验证。
3. **悬浮小窗拖动（长按触发）**：按住不动满 `VirtualScreenWindow.LONG_PRESS_DRAG_MILLIS = 350ms`
   （静置容差 `VirtualScreenWindow.DRAG_SLOP_DP = 8dp`）才改判成拖窗；在此之前的所有触摸照旧透传给副屏，
   所以副屏里的滚动、翻页不会被吞。改判瞬间给副屏补发一个 `cancel`（否则目标应用会停在「按下」状态），
   之后按 8ms 节流更新窗口位置并夹在屏幕内。**未在真机验证**：350ms 与 8dp 的实际手感，以及长按期间
   副屏自身的「长按」类操作（例如文本选择）是否与拖窗冲突。两个常量各集中在一处，便于后续调整
   （备选方案：双指拖动、加拖动手柄）。
4. **`virtualForegroundPackage` / `virtualForegroundActivity` / `autoFollow`**：由设备端提供。
   前台字段在约 800ms 的健康循环中刷新，逐帧状态读取只使用缓存；未解析到前台时返回空值。
5. **`stopVirtualScreen()`**：后台等待旧显示完成释放后才返回，前端可直接 `await stop` 后重启；
   超过 30 秒返回 `VIRTUAL_SCREEN_BUSY`，释放失败返回 `VIRTUAL_SCREEN_CLOSE_FAILED`，不继续自动重启。
   真机上的停止耗时未验证。
6. **启动竞态**：`startVirtualScreen()` 用 `VirtualScreenService.current != null` 判断「已在运行」，
   服务完成绑定前的极短窗口内重复调用会回到服务自身的 `current != null` 分支；真机行为未验证。
7. **设置页整链路**：本文只覆盖宿主侧；设置页组件与 `src/platform/**` 的桥接由另一侧实现，未在真机联调。

## 七、测试

纯函数逻辑都有 JVM 单测（无 Robolectric，直接 `./gradlew :app:testDebugUnitTest`）：

- `VirtualScreenBridgeTest`：写请求/启动请求的解析与错误码、0 与越界语义、状态合并的取值优先级
- `VirtualScreenStartTest`：五个来源的优先级、闸门、以及「任何输入算出的规格都过设备端闸门」
- `VirtualScreenDragTest`：长按判定（时间门槛、静置容差、非法输入）与拖动坐标夹取
- 既有：`VirtualScreenSizingTest`（预设与窗口几何）、`VirtualScreenPolicyTest` 等

`Intent`/`SharedPreferences`/`Context` 在 JVM 单测里是 not mocked 空壳，所以这两层读写
（`VirtualScreenSpec.decode` / `putVirtualScreenStart` / `VirtualScreenPreferences.read` / `apply`）
**没有单测**，只能靠真机验证。
