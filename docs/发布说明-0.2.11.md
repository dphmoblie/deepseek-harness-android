# 0.2.11 发布说明

本版把副屏预览从「逐帧 PNG 回传」改成「硬件帧直出 + 六档取帧」，并把副屏尺寸规格数据化；
同时加固会话列表契约与前端原生文件载荷校验。**副屏仍是实验性能力**，请以本页「未验证」一节
为准理解它的边界。

## 一、副屏高刷新率预览通道

- 取帧通道新增 AIDL 方法 `HardwareBuffer virtualScreenFrame(String sessionId) = 9`，
  `USER_SERVICE_VERSION` 从 4 提到 5。旧版本应用与新版本设备服务互相不匹配时，取帧会失败并
  如实回落到 PNG 路径，不会静默显示空白。
- 系统为 Android 11（API 30）及以上时，预览改用硬件帧直出：设备侧交出 `HardwareBuffer`，
  应用侧 `Bitmap.wrapHardwareBuffer` 直接上屏，**PNG 压缩与解码移出预览热路径**。
- 预览拉取间隔下限从 120 ms 降到 5 ms，档位由四档扩到六档；取帧与上屏分离，页面大预览与
  悬浮小窗共用同一条链路。
- 内容判定改为「硬件帧解码成功即视为有内容」，不再拿宿主按固定采样线算出的 `frameBlank`
  决定清不清屏；接近纯色的帧依然不上屏、也不清掉上一张画面，并在状态行如实写出原因。
- 硬件缓冲生命周期加固：取帧失败与过期帧会释放自己的缓冲，上屏时转移所有权，被丢弃与被清屏
  的帧会关闭缓冲，避免句柄泄漏。

## 二、副屏尺寸规格数据化

- 宽、高、DPI 从写死改为规格对象：竖屏 726 × 1600 / 320 dpi、横屏 1280 × 580 / 256 dpi
  两个预设数值保持不变；边长夹取到 200..4096、DPI 夹取到 120..640（夹取而不是报错）。
- 非法或缺失的参数回退到竖屏预设；只有旧版 `landscape` 布尔值的旧 Intent 仍然可用。
- 悬浮小窗的画面区按副屏宽高比适配，去掉此前因比例不一致造成的上下黑边；小窗仍限制在
  屏宽 90%、屏高 70% 以内，并保留拖动。
- 界面与文案去掉「实验功能」字样（能力边界不变，见「未验证」）。

## 三、契约与校验加固

- 会话列表载荷改为严格类型校验：`id` / `title` 必须是字符串，`updatedAt` 只接受 JSON 整数，
  不再把数值、`null` 或对象强制转成字符串或时间戳。
- 前端原生桥的文件载荷增加校验，非法载荷在平台层就被拒绝。
- 新增预览链路契约测试 `scripts/virtual-screen-preview-contract.test.mjs`，并把
  `scripts/mobile-compat-contract.test.mjs` 的 AIDL 事务号与设备服务版本断言补到当前值。
- 副屏创建时按 API 34 判断 `VirtualDisplayConfig` 的可用性（该 API 仅 Android 14 及以上存在），
  低版本走旧的 `createVirtualDisplay` 重载，避免 Android 12/13 上出现 `NoClassDefFoundError`。

## 四、验证范围（已跑过的）

- 上游 CI（构建 + 验证，含单元测试、`lintRelease`、脚本契约测试）在本版对应提交上为绿色。
- 本机 Kotlin 单元测试：89 个套件 / 820 条用例 / 0 失败 / 0 错误 / 22 跳过（跳过项是 Windows
  缺少 POSIX 符号链接能力的运行时用例，与副屏无关）；副屏子集 10 个套件 / 144 条用例 / 0 失败。
- 脚本契约测试：184 条用例 / 180 通过 / 0 失败 / 4 跳过。

## 五、未验证与已知问题

- **大预览页此前的两类现象**（全黑或纯色、有画面但不刷新）本次针对性改了取帧通道与内容判定，
  但**尚未在真机上复测确认**，请以实测为准。
- 悬浮小窗黑边是否真的消失、拖动是否正常、六档切换观感、长时间运行的掉帧与发热：均未在真机验证。
- 档位与屏幕刷新率尚未接线：`requestedRefreshRate()` 目前没有调用点，高刷模式里的 185 Hz 取值
  是写死的，档位实际只影响取帧间隔。
- 状态行里的帧率是**取帧帧率**，不是观看流畅度；「实际观看帧率 / 上屏耗时 / 截图耗时」三项指标
  本版没有补，因此「卡不卡」目前无法用数据证明。
- 运行时残留目录的清理在真机上仍然失败：严格删除器与兜底删除器都返回 `ACCESS_DENIED`，
  界面会如实显示残留份数与体积，但清不掉（不影响会话与当前运行时）。
- 外壳「会话工作区」的会话列表在本机读不出来，界面显示「读不到会话列表」而**不会**假装空态。
- 副屏上目标应用跳转到另一个应用会落在哪个显示器，只在机制上分析过（同任务留在副屏、跨应用
  默认跟随调用方所在显示、系统弹窗可能落在主屏），**未做实测**。
