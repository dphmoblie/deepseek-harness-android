# 诊断日志

设置里的「诊断日志」用于把设备上出现的问题带出来。它默认**关闭**，只在用户显式打开后
才开始记录，并且可以随时导出、分享或清空。

同一个页面下方还有一个**不会离开设备**的「运行日志」（Harness 访客进程输出尾部）：
它与诊断日志是两样东西，边界见下文《界面上的「运行日志」不是诊断日志》。

## 与审计日志的区别

| | 审计日志 `PrivateAuditLog` | 诊断日志 `DiagnosticLog` |
| --- | --- | --- |
| 用途 | 安全事件留痕 | 排障时间线 |
| 开关 | 不可关闭 | 用户开关，默认关闭 |
| 保留 | 固定 90 天 | 1–30 天（默认 3 天），可调 |
| 导出 | 不导出 | 可导出并分享 |
| 位置 | `noBackupFilesDir/audit/` | `noBackupFilesDir/diagnostics/` |

两者共享同一条底线：**只写受控枚举与受控键值**。

## 记录了什么

时间线覆盖排障最需要的几段：

| 事件 | 触发点 | 典型字段 |
| --- | --- | --- |
| `APP_START` | 插件加载完成 | `result` `active` `enabled` |
| `APP_DESTROY` | 插件销毁（含划掉最近任务） | `result` `active` |
| `RUNTIME_PHASE` | 运行时阶段变化（含失败码） | `phase` `reason` `code` |
| `HARNESS_START` / `HARNESS_STOP` | 启动（成功与失败都记）、停止 Harness | `result` `phase` `code` |
| `DEVICE_BRIDGE` | 设备桥创建 / 复用 / 失败 | `result` `code` |
| `KEEP_ALIVE` | 前台服务启停 | `reason` `active` `running` `enabled` |
| `RECOVERY` | 回收残留 Harness 进程 | `reason` `count` |
| `LOG_SETTINGS` / `LOG_EXPORT` | 日志自身的设置变化与导出 | `enabled` `days` `files` `bytes` |

一行形如：

```
2026-09-12T10:20:30Z|WARN|RECOVERY|reason=reaped_pid_file|count=1
```

### 启动失败也必须留下痕迹

只记成功是不够的：用户导出日志后若只看到 `HARNESS_START|result=ok`，
「dsh 为什么没起来」就无从复盘。因此**每一条把运行时阶段置为 ERROR 的启动路径**
（前置校验、Node/dsh 自检、端口占用、启动器装配、拉起进程、等待就绪、等待被中断、
访客进程自行退出……）都会写一条：

```
2026-09-15T10:20:30Z|ERROR|HARNESS_START|result=failed|code=HARNESS_START_TIMEOUT
```

- 记录只有 `result=failed` 与 `code`（受控错误码，取值来源见上文《一个必须写清的边界》）；
  运行时未安装、rootfs 校验不过这类**不改变阶段**的前置失败同样会被记下来。
- 写入集中在 `RuntimeSupervisor` 的启动失败统一出口（`failStart`）：新增失败路径只会走
  同一个出口，不会再出现「某个分支忘了记录」。记录内容由纯逻辑
  `HarnessStartFailurePolicy` 决定，并由它的单测锁定字段与事件。
- 访客输出、路径、端口、命令与凭据一律不写：失败原因只以受控错误码的形式出现。
- 分层：运行时层（`failStart`）覆盖面最广，凡把阶段置为 ERROR 的路径都在这里；
  `MobileRuntimePlugin` 的启动分支另有一条同样字段的补记，用来覆盖**运行时层之前**就失败的
  路径（`RUNTIME_BUSY` / `RUNTIME_CLOSED`、插件自愈等）。因此插件发起的失败可能看到两行
  相同的 `HARNESS_START|result=failed`：它们来自两层，不是重复故障。
  用户主动取消在运行时层不算失败（走取消分支，不记），插件层仍会如实写下一个
  `code=HARNESS_START_CANCELLED` 的 `failed` 行。

## 不记录什么

**绝不写入**：URL、端口、模型 API Key、Harness 临时 Basic Auth 密码、设备桥 token、
终端输入输出、文件路径、进程号、会话标识、异常消息文本、设备标识或账号信息。

保证来自三层，缺一不可：

1. **事件与级别是固定枚举**，不接受自由文本。
2. **字段名白名单**：只有 `phase` `code` `result` `reason` `enabled` `days` `files`
   `bytes` `count` `residual` `installed` `running` `permission` `connected` `active`
   `version` `sdk` `abi` 可以出现；`password` `token` `path` `api_key` 之类一律丢弃。
3. **字段值按类型校验**：布尔字段只接受 `true`/`false`；计数字段只接受 1–12 位数字；
   `code` 只接受大写错误码；`result`/`permission` 只接受封闭集合；`phase`/`reason`/
   `version`/`abi` 只接受小写 token。

非法字段被**丢弃**而不是让整行失败：事件本身比上下文更值得保留，且任何情况下都不会
写出不受控内容。

### 一个必须写清的边界

全大写且只含 `A-Z0-9_` 的字符串在**形态上**与错误码无法区分 —— `SECRETTOKEN` 与
`HARNESS_START_TIMEOUT` 同形。因此 `code` 字段的真实保证不是字符集，而是**取值来源受控**：
它只接受 `RuntimeFailure.code` 与状态快照里的 `errorCode`，两者都是固定的内部枚举，
永远不来自用户输入、WebView 或任何外部数据。字符集规则的作用是拦住小写、混合大小写、
含空格/引号/斜杠等自由文本形态。

## 界面上的「运行日志」不是诊断日志

设置 → 诊断与日志里有**两样不同的东西**，不要把它们的隐私边界混为一谈：

|  | 诊断日志（可导出） | 运行日志（只在界面） |
| --- | --- | --- |
| 内容 | 受控枚举 + 计数 | Harness 访客进程的 stdout/stderr 尾部（最近 8 KB） |
| 是否含用户数据 | **绝不包含** | **可能包含会话内容**（工具参数、报错栈、代码片段） |
| 存放 | `noBackupFilesDir/diagnostics/`，按保留期删除 | 只存在于运行时的输出缓冲区（内存） |
| 去向 | 用户显式导出并分享 | 只在设备上的设置页里展示，可手动复制 |
| 进导出吗 | 它就是导出内容 | **不进导出**，也不落盘、不新增诊断事件或字段 |

也就是说：诊断日志的承诺（不含终端内容或用户数据）**不因运行日志而放宽**，两者互不影响 ——
关掉诊断日志不会让运行日志消失，导出诊断日志也永远带不走它。

### 为什么需要它

工具调用失败时，界面只报一句**不带栈信息**的报错，排查无法进行；唯一能定位原因的线索，
是 dsh 自己打在 stdout/stderr 上的完整报错（Node.js 异常栈、插件加载失败原因等）。
为了既拿到这条线索、又不把它带出设备，读取入口做了三条限制：

1. **按需读取**：只有用户在设置页展开「运行日志（最近 8 KB）」时才读一次，进入设置页不读；
2. **只读有界**：原生侧最多回传最近 8 KB（`HarnessOutputTail` 按 UTF-8 字符边界截断，
   不会产生半个汉字），前端再校验 `available`/`text` 的类型与长度上限，非法载荷直接拒绝；
3. **只在界面**：文本按纯文本渲染（绝不解析为 HTML），不写入诊断日志、不落盘、不随导出离开设备。

运行时不持有 Harness 输出时如实返回 `available = false`，界面显示「当前没有可读取的运行日志」
并隐藏复制按钮，不猜造任何内容。运行日志的读取是只读接口，不改变诊断日志的开关、字段或保留策略。

## 定时删除

用户可设 1–30 天（默认 3 天）。删除时机：

- 每次写入前检查，若当天还没清理过就执行一次完整扫描（与审计日志同样的「每天一次」策略）；
- 删除「超出保留期」的文件，以及「目录总量超过 4 MB」时从最旧开始删除的文件；
- 单个日志文件上限 512 KB，达到后当天停止追加，避免单日刷爆存储。

本应用不引入 WorkManager 等后台调度依赖：清理发生在**应用或前台服务有活动时**。
这不会造成日志无限增长 —— 没有活动就没有新日志写入。

## 导出

「导出并分享」会把全部日志合并成一个文本文件，再由系统分享面板交给用户选择去向
（微信、邮件、文件管理器等）。文件头只包含：

```
# 应用版本 / Android SDK / ABI / 保留策略 / 内容说明
```

不含设备标识、账号、URL、路径或凭据。**也不含界面上的运行日志**（访客进程输出）与终端内容：
两者都不在诊断日志里，自然也不会被导出带走。

实现细节：日志本体在 `noBackupFilesDir`（不参与备份，也不可被 FileProvider 分享）；
导出时复制到 `cacheDir/diagnostics/`，通过只暴露该子目录的 `FileProvider`
（`${applicationId}.diagnostics`）以 `FLAG_GRANT_READ_URI_PERMISSION` 临时授权。
分享结束后导出文件仍在缓存目录，会被系统按需回收，也可用「清空日志」立即删除。

## 关闭开关时会发生什么

关闭只停止**新的写入**，不会删除已有文件 —— 用户可能先关掉再导出。需要立即清除请用
「清空日志」。已有文件仍受保留策略约束，到期会被自动删除。
