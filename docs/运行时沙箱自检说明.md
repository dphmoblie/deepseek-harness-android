# 运行时沙箱自检与权限修复

`sandbox_launcher=ok`、`sandbox_probe=PROBE_UNUSABLE` 表示启动器存在且有执行权限，但 Landlock 探测在当前环境中失败。可能是内核缺少支持，也可能是启动环境无法完成探测。不能仅凭这份结果断言是哪一种，更不能将单独的 `sandbox_exec` 或 `pty_sandbox` 失败当成所有沙箱后端均不可用。

“修复运行时权限”只补 `landlock-run`、`rg` 的执行位，并创建缺失的附件目录。它不能恢复缺失的程序，也不能增加内核能力。修复后自动重新自检，保留本次修复计数并以复检结果替换旧结果；复检失败会明确显示“自检未完成”。

## 在不支持 Landlock 的设备上继续使用

在当前 Harness 会话的权限预设中选择 `danger-full-access`，或者直接在会话输入：

```text
/permission danger-full-access
```

随后重试命令，例如让 Harness 的 bash 工具执行 `pwd`。**该预设会关闭 dsh 文件系统沙箱和命令审批**，进程仍受 Android 应用权限约束；PRoot 不提供额外的内核隔离。应用不会因自检失败自动选择此模式。

“设置 → 运行与后台 → Harness 启动权限”可设置启动默认值，保存后会重启已运行的 Harness，正在执行的任务会中断。该值通过 `DSH_PERMISSION_MODE` 注入 `env -i` 后的访客环境。dsh `0.1.5-rc.2` 中的优先级为：

1. 已有会话记录的权限保持不变，需要在该会话切换。
2. Harness 自身保存的 `permission.defaultPreset` 决定新会话默认值。
3. 没有保存默认值时，从应用注入的启动默认值推导权限。

因此仅重启不能保证改变旧会话。自检仍直接测试 Landlock，即使会话已关闭沙箱，相关检查仍可能失败；这不代表无沙箱会话的命令不能运行。

## 桥接契约

- 权限：只允许应用内部管理桥接调用现有的设置与自检接口。
- 参数：`harnessPermissionMode` 只接受 `workspace-write` 或 `danger-full-access`；省略更新保留原值。空值、非字符串和未知枚举拒绝。旧存储缺键或损坏时启动默认值回落至 `workspace-write`。
- 返回：设置与自检仅回传该枚举，自检中的值是检查时的启动默认值，不代表当前会话权限。不会返回命令输出、私有路径或凭据。

## 真机复测

1. 权限缺失时运行自检，点修复，确认自动复检更新结果；仍失败的 Landlock 项保留，修复按钮不会为此重复出现。
2. 在当前会话切到 `danger-full-access`，通过 Harness 的 bash 工具执行 `pwd`，确认无沙箱执行链路。
3. 保存应用启动默认值，确认运行中的 Harness 重启；分别验证全新会话、已设置 Harness 默认值的新会话和旧会话遵循上述优先级。
4. 切回 `workspace-write`，在当前会话也切回该预设；设备没有可用后端时应拒绝命令，不得静默回退。
5. 自检的裸 PTY 与沙箱内 PTY 分开判读：裸 PTY 通过、沙箱内失败时优先查沙箱；两者都失败时先查 PTY 和运行日志。
