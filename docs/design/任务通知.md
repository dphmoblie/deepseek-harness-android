# 任务通知

本文记录当前已经实现的任务状态通知。通知只报告确定的状态，不读取会话正文，也不承诺能阻止系统或厂商杀掉进程。

## 状态来源

Harness 内置的 `dsh-mobile-shizuku` 插件订阅 `session/event`，向本机设备桥尽力上报两类事件：

- `turn/start`：一轮任务开始；
- `turn/end`：一轮任务收口。

分别使用 `notify-turn-start` 和 `notify-turn-complete` 命令，经 `POST /device-command` 上报，不执行 Shell。两类请求使用同一套参数，当前插件会附带宿主提供的 `run`：

```json
{"session":"<16 位小写十六进制摘要>","turn":12,"reason":"turn-start","run":"<16 位小写十六进制代次>"}
```

`reason` 只接受 `turn-start`、`turn-end`、`turn-error`、`turn-aborted`、`turn-blocked`，结束通知据此区分完成、失败、取消和受阻；`interrupted`、`forked` 这类补写或派生事件不提醒。`session` 是摘要，不是会话 ID、路径或正文；`run` 用来隔离停止前后的迟到请求。原生按会话、轮次和开始/结束相位去重并处理乱序，不能按 HTTP 到达顺序推断任务状态。

插件请求使用已有设备桥鉴权，超时 2 秒，不等待、不重试、不把失败传回 Harness。插件被关闭、没有设备桥、旧插件没有刷新成功或事件本身没有产生时，原生收不到信号，也不会伪造通知。

## 进行中状态

原生在内存中维护每个会话最近一轮的开始/结束状态。收到合法的 `turn/start` 后，应用在后台显示一条进行中通知；收到对应的 `turn/end` 或其它合法结束原因后撤下它。状态保存在进程内，不写盘，进程被系统回收后需要重新连接。

进行中通知使用独立的 `dsh_active_tasks_v2` 通道（`IMPORTANCE_DEFAULT`，关闭声音、振动与角标；首次升级或打开通知设置时会清理旧的低重要级 `dsh_active_tasks` 通道，避免 HyperOS / MIUI 将其折入「不重要通知」而抑制状态栏和岛态提升）和 `0x44534806`，与保活、悬浮球和结果通知互不覆盖。为避免实况提升节点与后台折叠组摘要（`0x44534800`）在部分 Android 16/17 系统（如荣耀 SystemUI `ShadeViewDiffer.registerNodes`）发生 `DuplicateNodeException` 节点重复冲突，`0x44534806` 刻意**不**加入 `BackgroundNotificationGroup`。它只在后台显示，不响铃、不振动、不弹横幅；应用回到前台时撤下，刷新时发现通知未授权也不会显示。

信号丢失有 6 小时上限：超过 6 小时没有新的事件，原生把该轮视为失效并撤下进行中通知。这个上限是兜底，不代表任务一定成功或失败。

Android 16（API 36+）设备上，进行中通知优先使用原生 `Notification.Builder` + `Notification.ProgressStyle`（不确定进度），调用原生实况请求并传入短状态文本，同时通过 `hasPromotableCharacteristics()` 校验结构并在异常时回落到标准原生或 `NotificationCompat` 通知。设置页「后台保持」会通过 `canPostPromotedNotifications()` 如实展示「实时动态通知」授权状态并提供系统设置跳转（未授权或结构不满足时在诊断日志记一条去重警告）。不同 Android 版本和厂商（包括小米 HyperOS 各版本的超级岛 / 焦点通知白名单与侧载限制）对实时展示、锁屏和后台调度的处理不同，应用不承诺任何 OEM 一定显示超级岛或实时卡片。

## 完成与操作结果

完成事件使用 `dsh_tasks` 通道和 `0x44534804`；安装、更新、修复、导入导出和异常退出等操作使用同一通道的 `0x44534803`。悬浮球和保活通知各自使用独立的通道与 ID，清理任务通知不会误删它们。

完成通知只在应用后台且通知权限可用时投递。连续事件在 1.5 秒静默窗口内合并，窗口最多等待 10 秒，两次投递至少间隔 6 秒，单条最多显示 20 个完成项。应用在前台时不弹通知，但进程内完成计数仍会更新；回到应用后任务通知会清理。

所有通知文案来自固定资源，不包含会话正文、路径、凭据或用户输入。通知点击只打开应用的既有转发入口，不执行破坏性动作。

## 权限与降级

Android 13 及以上需要 `POST_NOTIFICATIONS`。用户拒绝后 Harness 仍可运行，但后台进行中和完成提醒不可用；应用设置页会如实显示状态，并允许用户之后重新授权。应用不会偷偷改用第二个常驻服务来绕过拒绝。

每次 Harness 启动都会从当前 APK 刷新 `turn-signal.js` 到已安装 rootfs，再启动插件。这样旧 Ubuntu rootfs 也能获得当前的开始/结束协议；只更新 APK 或只更新 rootfs 都不能替代启动时刷新。

## 明确边界

- 这不是保活机制，不能阻止 Android 或厂商系统结束进程。
- 没有持续的 guest→native 心跳、百分比或实时进度；拿不到的状态不显示。
- 插件关闭、旧运行时未能刷新、设备桥不可用或事件上报失败时，不会出现任务通知；用户应回到应用查看实际状态。
- 锁屏可见性由通知本身和通道共同请求为公开，但已创建的 Android 通道可能保留用户旧设置，厂商也可能进一步限制显示。

验收至少覆盖：开始后后台出现进行中通知、结束后撤下；Android 16 promoted ongoing 与普通通知降级；6 小时无信号自动失效；关闭通知权限和关闭插件时不伪造提醒；旧 rootfs 启动后能收到当前插件发出的开始/结束事件；任务通知与保活/悬浮球通知互不覆盖。
