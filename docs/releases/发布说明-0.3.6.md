# 0.3.6 更新说明

## 本版重点

- **修复 Shizuku UserService 启动即崩溃（表现为「Shizuku 连接未就绪 / 连接超时」）**：
  0.3.5 的 `network-security-config` 是「`base-config` 允许明文 + 一条只含
  `127.0.0.1`/`localhost` 的 `domain-config`」。AOSP 的
  `NetworkSecurityConfigProvider.handleNewApplication()` 在**共享进程**里发现两个 Application
  的进程级明文策略不一致、且任一方带按域名规则时，会直接抛
  `Found multiple conflicting per-domain rules`。Shizuku 13.6.0 起，UserService 会在同一进程里
  为目标应用创建 Application（`LoadedApk.makeApplication`），于是这份配置正好踩中；
  13.5.4 不创建 Application，所以同一份 APK 换回旧版 Shizuku 也能连上。
  现在只保留 `base-config`：没有按域名规则后，同进程的策略不一致只会记一条警告并按较宽松的
  配置继续，不再抛异常。回环与自定义 HTTP 供应商所需的明文策略不变，远程下载/目录仍走 HTTPS 校验。
  （0.3.4 是「`base-config` 禁止明文 + 回环 `domain-config`」，进程级策略与系统默认一致，
  所以配 13.6.0 也不会崩——这也是「只换 Shizuku 版本就恢复」和「只换 APK 版本就恢复」
  两种对照实验都成立的原因。）
- **修复预览「分享」点击后报「文件操作失败」**：页面给出的相对路径是按会话工作目录算的，
  会话未绑定工作区时地址里会多一层 `1/`（对应 PRoot 的 `/root`），原生曾经把它再拼成
  `/root/1/1/…`，于是永远找不到文件。现在原生对「相对工作区」和「相对 `/root`」两种口径
  都给出候选，按工作区里是否真有这个普通文件决定用哪个；两个候选都只描述 `root/1` 下的路径，
  逐层 NoFollow 校验不变，分享范围没有扩大。仍然找不到时提示改为「工作区里找不到这个文件，
  无法分享」，与真正的读盘/复制失败区分开。
- **发布版不再混淆代码**：关闭 R8（`minifyEnabled false`），并继续关闭资源裁剪
  （`shrinkResources false`）。本包体积的绝大部分是 rootfs，混淆收益可以忽略；而 Shizuku
  的 UserService、Capacitor 插件注册、`FileProvider` 都按名字工作，混淆后只会表现为
  「连接超时」「文件操作失败」这类误导性错误。注意：AGP 的资源优化仍会把
  `res/xml/network_security_config.xml` 改名为 `res/8G.xml`，这一项由
  `android.enableResourceOptimizations` 控制，本版不打开。

## 升级提示

- 本版只有 APK 侧改动，运行环境内容没有变化；更新运行环境仍会替换其中的本地修改
  （用 apt 等装进系统的软件等），重要数据请先另行备份。
- 之前为定位 Shizuku 连接受阻而临时用独立包名（`io.deepseekharness.mobile.shizukutest`）
  装过测试包的设备，请手动卸载该测试包；本版已去掉这个临时包名后缀，安装包身份回到
  `io.deepseekharness.mobile`。
- 仍停留在 0.3.5 及更早版本的设备，如果 Shizuku 是 13.6.0，可以在升级前先临时改用
  Shizuku 13.5.4（需卸载重装后重新授权）绕过「Shizuku 连接未就绪」；升级到本版后不必再降级。

## 验证限制

- 前端测试、脚本测试、`tsc`、ESLint、生产构建、`gate-check` 与 Android JVM 单元测试通过；
  Kotlin 编译无错误。
- **Shizuku 崩溃修复**已在一台真机（HONOR，Android 17）上用临时包名安装验证：修复后
  UserService 不再在启动时崩溃，Shizuku 连接恢复正常；该测试包用的是 APK 内的完整运行时，
  未覆盖远程下载更新的路径。
- **分享路径修复只做了单元测试与静态分析，尚未在真机复测**（排查结束后没有再连接设备）。
  仍需在真机安装后确认：预览面板顶栏出现分享按钮，点击后能调起系统分享面板，且分享出的
  文件内容与预览一致。
- 资源路径改名的构建开关未调整，`res/xml/network_security_config.xml` 在 APK 内仍是短名，
  本版没有对这一点做额外验证。
