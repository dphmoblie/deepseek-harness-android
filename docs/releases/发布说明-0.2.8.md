# 0.2.8 测试版：删不掉的残留改用兜底删除器回收

基线是 0.2.7（`versionCode 29`）在真机上留下的两条读数：

1. 清理失败的状态码全是 `code=FILESYSTEM`，来自 `RuntimeRetireTokens.classify()` 里
   `is FileSystemException -> "FILESYSTEM"` 那一个分支 ⇒ 真机上抛的是 `java.nio.file.FileSystemException`
   这一族（不是 `ErrnoException`），而 `AccessDeniedException` / `DirectoryNotEmptyException` /
   `NoSuchFileException` / `NotDirectoryException` 都是它的子类，会被父类先吃掉、丢掉区分度。
2. 严格删除器（走 `SecureDirectoryStream`）在真机上删不掉那份 `previous/`，0.2.7 只能把它改名成
   `stale-previous-*` 挪开 ⇒ 更新不再被挡住，但**残留回收不了**，每轮更新多占一份 rootfs（界面读数约 960 MB）。

## 改动

- **清理失败的状态码细分**：`RuntimeRetireTokens.classify()` 在 `is FileSystemException` **之前**插入
  `is AccessDeniedException -> "ACCESS_DENIED"`、`is DirectoryNotEmptyException -> "NOT_EMPTY"`、
  `is NoSuchFileException -> "NO_SUCH_FILE"`、`is NotDirectoryException -> "NOT_A_DIR"`。
  顺序不能反：子类排在父类后面就会全部塌成 `FILESYSTEM`，真机上就又看不出「权限被拒 / 目录非空 /
  条目已经消失」的区别了。
- **新增不跟随符号链接的兜底删除器**：`RuntimeFiles.deleteTreeNoFollowFallback(root, allowedParent)`。
  与严格删除器的差别是**不使用 `SecureDirectoryStream`**：改用 `Files.readAttributes(..., NOFOLLOW_LINKS)`
  判断类型，目录先递归清空再 `Files.delete`，符号链接只删链接本身、绝不下降；作用域校验
  （根目录必须直接位于运行时父目录下，否则 `RESET_SCOPE_INVALID`）、深度上限 `MAX_DELETE_DEPTH = 256`
  与条目预算 `MAX_DELETE_ENTRIES = 250_000` 与严格删除器完全一致。
- **`retireIfPresent` 变成三级回落**：严格删除器 → 兜底删除器 → 改名挪开。兜底删除成功时记一条
  `phase=cleanup|result=succeeded|code=<严格删除器的失败类别>|reason=fallback_<名字>|count=0`：
  既证明残留被真正回收，也留下「严格删除器在真机上会失败」这个事实。同族残留（`stale-<原名>` 与
  `stale-<原名>-*`，最多 3 份）同样先走这两条删除路径再考虑改名。两条删除路径都失败才改名挪开，
  并照旧记 `result=failed` + `result=skipped`。
- 版本号 0.2.7 → 0.2.8（`versionCode 30`）。
- 上一版内容见 [发布说明-0.2.7.md](发布说明-0.2.7.md)、[发布说明-0.2.6.md](发布说明-0.2.6.md)。

## 未解决的设备限制

- **严格删除器为什么在真机上失败仍未查清**（0.2.7 的 `code=FILESYSTEM` 只能证明是
  `FileSystemException` 这一族）。0.2.8 的兜底删除器是**绕过**而不是修好它；活路径
  （`current/`、`previous/`、`staging-*`）依旧走严格删除器，只有已经不再需要的残留才走兜底。
- 兜底删除器不再持有目录描述符，因此存在 TOCTOU 窗口；它只用于运行时目录下、由本应用自己生成的路径，
  且仍要求根目录直接位于运行时父目录之下。
- 若**兜底也删不掉**（例如文件被占用），行为仍是改名挪开：每轮更新会新增一份 `stale-*`，
  磁盘占用继续增长，诊断日志里出现 `result=failed` + `reason=stale_*`。
- 副屏相关限制与 0.2.7 相同：需要 Shizuku 授权与 Android 10 及以上；触摸直传（`touchChannel=stream`）
  依赖隐藏接口 `InputManager.injectInputEvent`，被 ROM 拦掉时回退到离散的 `input -d <显示编号>`；
  节点树与中文注入要求用户手动开启应用的无障碍服务。
