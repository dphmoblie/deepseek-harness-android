# 0.4.3 发布说明（测试版）

本版是当前 `main` 的测试版构建。功能代码与主分支一致，仅提升版本号并重新生成 APK 与运行环境；
重点验证悬浮球细线收起、后台通知合并、运行时启动修复与加密数据备份。

## 相对 0.4.2 的主要变化

- **悬浮球**
  - 默认收起为贴屏幕边缘的 8 × 74dp 细线，窗口仍保留 44dp 触摸热区，不遮挡正文。
  - 单击展开为 48dp 圆球并显示二级入口；长按直接打开 Harness 对话小窗。
  - 展开后 3 秒无操作自动收回；拖动时临时显示 28dp 胶囊，松手吸附最近边缘。
  - 细线/圆球形态写入独立偏好，服务重启后沿用上次状态。
- **后台通知**
  - 任务进度、任务完成、Shizuku 提醒、保活、悬浮球与副屏通知统一进入 Android notification group。
  - 通知栏折叠时只保留一条组摘要，显示后台通知数量；展开后仍可查看每条子通知。
  - 组摘要使用独立的低优先级静默通道，任务完成等子通知仍按原策略提醒。
- **运行时启动**
  - 修正 dsh 全局 `--patch` 参数位置：补丁选项移到 `web` 之前，避免 `unknown option '--patch'` 导致 Harness 启动后立即退出。
  - Harness 启动追加 `--no-open`，不再调起系统浏览器。
  - 启动/打开在生命周期锁被另一个起停事务占用时按 100ms 分片等待并重查长操作闸门，无长操作时以 15 秒封顶。
- **数据备份**
  - 会话、设置、模型凭据、技能与附件统一纳入数据备份，生产环境逐文件使用 Android Keystore 加密。
  - 上限调整为 10 份 / 16 GiB；旧版明文快照仍可只读恢复。
  - 恢复设置与凭据时继续保持 0600 权限。
- **dshmarket**
  - 将 `@deepseek-ai/schemastery` 从可选 peer 提升为直接依赖，修复真机 profile 缺链导致的 `Cannot find module`。
  - 构建期增加校验：dshmarket 与它的 peer 必须落成 `profiles/node_modules` 的扁平链接，缺链直接失败。
- **副屏**
  - 控件树读取改用 `getWindowsOnAllDisplays()` 按 displayId 获取窗口，并补充 API 30 守卫；副屏不再误读默认显示屏。
- **诊断日志**
  - 默认附带可选的 Harness 运行日志尾部，导出前二次确认；可随时关闭。
- **版本管理**
  - 恢复「Harness 上游版本」区块，可自由安装、切换、删除 dsh npm 版本。
  - 版本管理卡片统一为主题卡片，刷新设计令牌与旧版 WebView 兜底。

## 验证

- 本机：`tsc -b`、ESLint、`node scripts/gate-check.mjs` 4/4、前端全量测试、Android `lintDebug` 与 JVM 单测通过。
- 发布流水线会重新执行前端、脚本、Android JVM 单测、签名 APK、rootfs 与资产校验；
  以 Release 中实际产出的 `app-release.apk`、`rootfs.bundle`、`runtime-manifest.json` 为准。

## 安装

1. 安装 `app-release.apk`（离线 APK，已内置 PRoot 运行器与 Ubuntu rootfs）。
2. 首次打开后按引导安装运行环境；rootfs 从 APK 内置资产解压，无需联网下载。
3. 旧版本升级时可保留已有会话与工作区；运行环境更新/回退的保留项见版本管理页。
