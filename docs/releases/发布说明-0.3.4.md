# 0.3.4 更新说明

## 本版重点

- **修复老系统 WebView 上「选择工作区目录」直接报错**：系统 WebView 低于 Chrome 124 时没有
  `AbortSignal.any`，Harness 页面点开目录选择会显示「AbortSignal.any is not a function」，
  目录列不出来、只能取消。现在会在页面加载完成后把这个 API 补上，只在缺失时补，新 WebView
  上不做任何改动，目录选择恢复正常。
- **修复切换上游 Harness 版本时的三处问题**：
  - 安装上游版本时 npm 在 PRoot 访客里全部超时（IPv6 不可达叠加 Node 24 的地址族自动选择），
    安装停在「解析依赖版本」阶段；现在只为 npm 子进程关闭地址族自动选择并优先 IPv4。
  - 上游 0.2.1-rc.2 起把 `dsh.bundle.patch` 从字符串改成有序数组，切换时被误判为配置无效并
    自动回滚；现在两种声明都能识别。
  - 安装阶段进度事件没有转发到界面，进度条一直停在「准备中…」；现已补齐。
- **上游版本补装 Android 适配层**：上游 npm 包自带的官方前端没有我们的移动端布局、安全区
  适配和外置浏览器会话续接。现在安装与切换时会从内置运行时复制适配文件并注入 `index.html`，
  校验通过的包才会补装，新增文件同步记入完整性清单。
- **外置浏览器续接应用内会话，并在打开时自动检测 Shizuku**：外置浏览器打开 Harness 时会
  带上应用内当前会话，不再新建一段对话；打开前自动触发一次 Shizuku 授权检测，减少「明明
  授权过却提示未授权」的情况。

## 升级提示

- 本版只有 APK 侧改动，运行环境的内容没有变化：若应用提示更新运行环境，按提示更新即可，
  不更新也不影响本版修复生效。
- 更新运行环境仍会替换其中的本地修改（用 apt 等装进系统的软件等）。程序的自动保留与恢复
  机制不能代替完整备份，重要数据请先另行备份。

## 验证限制

- 前端测试、脚本测试、`tsc`、ESLint、生产构建与 `gate-check` 通过；Android Kotlin 编译与
  JVM 单元测试通过。补丁脚本的行为另有 JVM 单测钉住「只在缺失时补」「reason 语义」
  「非信号入参抛 TypeError」「可重复执行」四条约束。
- 「选择工作区目录」的修复属于 WebView 运行时行为，只能在设备上复测：装新 APK 后点一次
  目录选择，能列出目录即生效；若仍报同一个错，说明那段访客代码在模块加载时就取了 API 引用，
  需要改成 document-start 注入。
- 上游版本管理已在真机完成一次真实安装与切换（0.2.1-rc.2），运行时以该版本启动；补装适配层
  后页面确认加载 `dsh-android.css` 与会话脚本，移动端不再横向溢出（363px 视口下滚动宽度由
  1440px 恢复为 363px）。
- 已知限制：切换上游版本后不会应用内置运行时的四个源码补丁（含 PRoot `link(2)` 文件系统
  兼容）与 zod/undici 安全版本覆盖；兼容性仍以「切换时实际启动检查、失败自动回滚」兜底。
