# 0.4.4 发布说明（测试版）

本版是 0.4.3 的启动修复版，重点修复运行时更新后 Harness 无法启动：
dsh 命令行带 `--patch` 时必须显式提供 `--profile <name>`，否则会直接退出并显示
`error: --profile <name> is required`。

## 相对 0.4.3 的修复

- **Harness 启动**
  - `RuntimeCommand.withPatch` 现在把命令组装为
    `dsh --profile web --patch FILE ...`，补丁参数不再依赖 dsh 的隐式 profile 补全。
  - provider patch 与 plugin patch 可以叠加，`--profile` 只出现一次。
  - `--no-open` 追加到应用参数末尾，避免排在 `--patch` 之前被当成未知全局选项。
  - 新增单测覆盖单补丁、双补丁叠加、`--no-open` 位置与幂等性。
- **运行时更新后的行为**
  - 更新流程本身仍由生命周期锁保护；本次没有移除锁，也没有放宽 rootfs 写入互斥。
  - 若日志里仍出现 `RUNTIME_OPERATION_BUSY`，它表示确有长操作持有锁，不再是启动命令本身失败。

## 验证

- `RuntimeModelProvidersTest` 通过。
- 发布流水线会重新执行前端、脚本、Android JVM 单测、签名 APK、rootfs 与资产校验；
  以 Release 中实际产出的 `app-release.apk`、`rootfs.bundle`、`runtime-manifest.json` 为准。

## 安装

1. 安装 `app-release.apk`（已内置 PRoot 运行器与 Ubuntu rootfs）。
2. 首次打开后按引导安装运行环境；rootfs 从 APK 内置资产解压，无需联网下载。
3. 从 0.4.3 升级时保留会话与工作区；更新运行环境后 Harness 应能正常启动。
