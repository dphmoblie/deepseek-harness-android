# 0.4.6 发布说明（测试版）

本版是当前 `main` 的测试版构建。相对 `0.4.5`，本次重点放开 8 项 AI 宿主与设备能力并全部收归启动器硬编码细分开关，同时完成全量高危命令与跨通道防自我提权加固，并包含会话归档管理与外部分享修复。

## 相对 0.4.5 的主要变化

- **AI 宿主与设备权限放开（4 组共 25 项硬编码细分开关）**
  - 在原有 17 项高危文件/命令开关基础上，新增第 4 组「宿主、沙箱与设备权限放开（8 项）」，支持按需显式开启：
    - Root 解除沙箱命名空间隔离、Root 跳过应用警告确认页直通、AI Shell 执行前置授权放开；
    - 无障碍操作受保护系统应用、无障碍读取与操作敏感/密码窗口；
    - 设备文件跨目录全局读写、外置 URL 自定义 Scheme 放开、访客环境整张 `/sdcard` 读写挂载。
  - 所有开关默认关闭并持久化保存；关闭总开关或对应细分项后，宿主立即恢复原生硬编码拦截，不依赖 AI 自觉。
  - 界面文案同步覆盖简中、繁中、英、日、韩五种语言。
- **高危命令拦截规则深度加固与误伤修正**
  - 封堵 Shell 混淆与逃逸向量：拦截命令位置变量展开（`$a$b`）、通配符路径（`/system/bin/reboo?`）、ANSI-C 转义（`$'\x72...'`）、`alias` 别名、管道/非 `-c` 二次 Shell（`| sh`、`sh -s`、`sh <file>`）以及脚本解释器内联执行（`awk system()`、`python -c` 等）。
  - 新增 `cd`/`pushd` 相对路径追踪与绝对路径 `..`/`//` 规范化，拦截切换目录或路径穿越后的相对路径删改与重定向（如 `cd /sys/fs/selinux && echo 0 > enforce`、`cd /data && rm -rf system`、`rm -rf /data/local/tmp/../../../system/bin`）。
  - 补齐前置重定向（`</dev/null reboot`）、`rm -rf /`、核心分区删改、`/data/adb/service.d` 与 `/data/system` 重定向写入、`settings put`/`pm grant`/`appops`/`dpm`/`killall`/`magiskpolicy` 等高危系统控制纳管。
  - 修正误伤：`sed -n` 只读读取系统文件、`find /data/local/tmp/... -delete`、`find . -name ...`、`command -v su` 等常规运维命令恢复低风险直通。
- **跨通道防 AI 自我提权**
  - Root 高危警告确认页启用 `FLAG_SECURE` 与防遮挡触控过滤；确认页打开期间，无障碍服务无条件硬拒绝一切页面读取与点击（即使已开启敏感窗口开关）。
  - 本应用高危权限设置页受五语防自我点击护栏保护，防止 AI 借无障碍替自己开启高危权限开关。
  - AI 副屏永久禁止拉起本应用自身（`VIRTUAL_SCREEN_TARGET_FORBIDDEN`）；受保护系统包清单补齐 KernelSU/Magisk/APatch/Shizuku 管理器及主流国产 ROM 安全中心与权限管理器，未开启系统应用开关时禁止副屏与无障碍接管。
- **会话与文件管理**
  - 首页会话区按归档状态分档展示，并支持删除已归档会话。
  - 外部文件分享改用路径兜底，目录列表过期时自动刷新。

## 验证

- 本地已通过 TypeScript、ESLint、Vitest（83 套件 / 1107 用例）、脚本契约测试（444 用例）、`gate-check.mjs`（4/4）与 Android JVM 单元测试（1777 用例，含红队绕过与误伤回归）。
- 发布流水线会重新执行全量前端、脚本、Android 单测、lint、签名 APK、rootfs 与资产完整性校验；以 Release 中实际产出的 `app-release.apk`、`rootfs.bundle`、`runtime-manifest.json` 为准。

## 安装

1. 安装 `app-release.apk`（已内置 PRoot 运行器与 Ubuntu rootfs）。
2. 首次打开后按引导安装运行环境；rootfs 从 APK 内置资产解压，无需联网下载。
3. 旧版本升级时保留会话、工作区与既有设置；25 项高危细分权限默认全关，可在「设置 → AI 高危权限」按需开启。

沿用 [0.4.0 发布说明](发布说明-0.4.0.md) 中的已知限制；根通道、副屏与国产 ROM 的应用列表及无障碍权限仍需按机型复测。
