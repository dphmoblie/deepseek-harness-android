# 更新与推送规范（中文说明要求）

本文档阐明本仓库在进行代码提交、分支推送、Pull Request 与版本发布时的中文更新说明规范。

---

## 1. 规范背景与原则

- **统一中文语义**：项目代码库内的主要文档、提交日志（Commit History）、Pull Request 说明及发版公告一律采用**简体中文**进行记录与说明。
- **改动清晰可追溯**：提交信息必须阐述清晰的改动动机（为什么改）、变更内容（改了什么）以及产生的影响（是否影响现有功能/依赖）。
- **拒绝模糊提交**：严禁使用 `update`、`fix`、`modify` 等无具体信息的提交信息。

---

## 2. Git 提交信息（Commit Message）规范

提交信息遵循约定式提交（Conventional Commits），核心摘要行建议在 50 字以内。

### 2.1 格式要求

```
<类型>(<可选影响范围>): <简短中文概述>

【详细变更说明】（可选，列出关键改动细节与原因）
- 改动点 1
- 改动点 2

【关联需求 / Issue】（可选）
- 需求编号或关联 Issue #123
```

### 2.2 提交类型（Type）对照表

| 类型 | 意义说明 | 示例 |
| :--- | :--- | :--- |
| `feat` | 新功能、新特性支持 | `feat(副屏): 增加出口芯片与全屏预览支持` |
| `fix` | 缺陷修复、异常处理 | `fix(设置页): 修复设置卡片边界滚动衔接失效问题` |
| `docs` | 文档编写与更新 | `docs: 新增更新推送中文说明规范` |
| `style` | 格式美化、排版（不改变运行逻辑） | `style: 格式化终端输出组件缩进与分号` |
| `refactor` | 代码重构（既不新增特性也不修复缺陷） | `refactor: 抽离副屏渲染状态管理模块` |
| `perf` | 性能调优、渲染优化、减少重绘 | `perf: 优化渲染树遍历减少空转 tick 重绘` |
| `test` | 增加或调整单元测试、回归用例 | `test: 增加版本更新检查对话框边界测试` |
| `chore` | 构建流程、依赖版本、辅助工具等变动 | `chore: 升级 eslint 配置并补充自检脚本` |

---

## 3. 分支推送与 Pull Request 规范

当向 GitHub 远程仓库推送代码并发起 Pull Request 时：

1. **PR 标题**：格式同 Commit Message，必须为清晰中文（例如：`feat(设置): 固定应用启动入口并移除自动启动开关`）。
2. **PR 模板**：仓库已在 [`.github/pull_request_template.md`](file:///.github/pull_request_template.md) 配置中文模板，发起 PR 时请按模板逐项勾选并补充：
   - 更新概述
   - 变更类型
   - 详细改动清单
   - 验证与测试结果（本地已跑通 `pnpm run test`、`pnpm run lint`、`pnpm run build`）
   - 关联需求或 Issue 编号

---

## 4. 版本发布说明（Release Notes）

根据项目的 CI 流水线（`.github/workflows/android-build.yml`）：
- 每次版本迭代发版时，发布说明统一在 `docs/发布说明-<版本号>.md` 文件中用中文撰写。
- CI 构建完成后，会自动读取该文件中的中文说明并发布至 GitHub Release 页面。

---

## 5. 本地 Git 提交模板配置

仓库根目录已内置 [`.gitmessage`](file:///.gitmessage)。可通过执行以下命令让本地 git 默认启用该提交模板：

```bash
git config commit.template .gitmessage
```
