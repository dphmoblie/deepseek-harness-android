# 运行时更新与访客数据保留

## 问题

每次升级运行时（在线更新或安装 APK 内置的新 rootfs），访客里的**全部用户数据都会丢失**：
对话会话、用户自己安装的插件、dsh 配置文件。

成因在 `RuntimeInstaller.promoteStaging()`：

1. `currentRoot`（`noBackupFilesDir/dsh-runtime/current`）改名为 `backupRoot`；
2. 新解压的 `stagingRoot` 改名为 `currentRoot`；
3. **`cleanupIfPresent(store.backupRoot)` 直接删掉旧根目录**。

而 dsh 的用户数据写在访客的 `$DSH_HOME`（即 `/root/.dsh`，对应宿主
`currentRoot/root/.dsh`）里，因此第 3 步等于把用户数据连同旧根目录一起删除。
应用内那句「更新会替换当前 Ubuntu 根目录…未导出的文件将被清除」正是这个行为的描述。

已知的访客数据位置（由仓库脚本佐证）：

| 路径 | 内容 | 是否保留 |
| --- | --- | --- |
| `root/.dsh/sessions` | 对话会话（见 `scripts/mobile-session-publish.py` 的 `SESSION_ROOT`） | **保留** |
| `root/.dsh/plugins` | 用户安装的插件 | **保留** |
| `root/.dsh/projects` | 工作区/项目状态 | **保留** |
| `root/.dsh/settings.json` | dsh 配置 | **保留** |
| `root/.dsh/profiles/` | `profiles/web/*`、`profiles/node_modules/*` | **不保留** |
| `root/.dsh/{cache,tmp,logs}` | 运行时缓存与日志 | **不保留** |
| `root/.dsh-mobile/launcher-providers.patch.json` | 应用生成的启动配置 | 不保留（每次启动重新生成） |

## 为什么是白名单，而不是整个 `$DSH_HOME`

`root/.dsh/profiles/node_modules/*` 是**指向 rootfs 内包的符号链接**，
`profiles/web/*` 也是按当前 dsh 版本生成的产物。
把旧版本的 `profiles` 整体搬进新根目录会同时制造两类问题：

- 悬空符号链接（旧 rootfs 已被删除）；
- 新旧两套运行时模块并存 —— 这正是 `docs/ARCHITECTURE.md` 的
  「运行时依赖版本钉与 Symbol 身份」小节所述「同名包出现两份物理副本会让 Symbol 身份不一致」
  的同一类故障。

因此只搬运明确的用户数据，运行时产物一律由新 rootfs 提供。

## 实现约定

1. 新增强制性白名单对象 `RuntimePreservePolicy`（`runtime` 包），
   只列出上表「保留」的项；任何不在白名单内的名字（含 `../`、绝对路径、含 `/` 的项）
   一律拒绝。白名单用**扁平名字**而非嵌套路径，避免引入路径穿越面。
2. `promoteStaging()` 在**备份旧根目录之前**把白名单项移出到
   `runtimeParent/preserve-<uuid>/`，提升完成后再移回新根目录的同一相对路径。
3. 回滚路径同样要还原：`rollbackPromotion()` 之后必须把已移出的项放回恢复出来的旧根目录，
   否则「回滚」本身就会造成数据丢失。
4. 回填时的冲突判定必须区分「空壳」与「有内容」，否则会误判：

   - 新根目录**不存在**该同名项 → 直接移入（正常路径）。
   - 新根目录存在一个**空目录** → 视为 rootfs 自带的空壳（镜像很可能预建空的
     `sessions/`、`plugins/` 目录），删除空壳后把用户数据移入。
     若不这样做，每次正常更新都会被判成冲突而失败。
   - 新根目录存在**非空目录或文件** → 判定为真冲突：保留用户数据不动、不覆盖也不删除，
     返回未回填清单并抛 `RUNTIME_PRESERVE_FAILED`；此时**不得删除 `backupRoot`**，
     以便用户排查或人工取回。
5. `recoverInterruptedPromotion()` 在存在遗留 `preserve-*` 目录时，
   不得按「当前与备份都有效」分支删除 `backupRoot`。
6. `resetWorkspace()` 属于用户显式清空运行时，可以一并清理 `preserve-*`。
7. 移动一律用 `Os.rename`（同一私有目录内，避免跨设备拷贝与半途中断）。
8. 迁移失败必须表现为**受控错误码**，不得静默降级。

## 验收要点

- 单元测试覆盖 `RuntimePreservePolicy` 的白名单与拒绝路径（含 `../`、绝对路径、嵌套名）。
- 真机验收：安装 v1 → 建一个对话 → 更新到 v2 → 会话与已装插件仍在。
- 真机验收：更新过程中断（回滚路径）后，旧会话仍在。

## 相关但独立的待办

以下两项与运行时更新同属「存储边界」议题，但改动面独立，不并入本次修复：

- **访客可见目录收紧**：当前 `RuntimeLaunchResolver` 里有一条把 `/sdcard` 整体绑定进访客的
  可选绑定；应改为由用户选择多个目录（上限 8 个），分别挂到固定的访客路径
  （`/workspace`、`/mnt/<slug>`），并且只绑定被选中的目录，而不是整个 `/sdcard`。
  SAF 的目录树 URI 不是文件系统路径，需要先映射为真实路径并经用户确认。
- **存储权限 UI**：照片/视频权限的申请入口，以及 Android 11+ 的「所有文件访问」状态与设置页入口
  （低于 Android 11 隐藏该入口）。
