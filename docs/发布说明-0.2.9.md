# 0.2.9 测试版：修好悬浮球闪退，悬浮球改为二级菜单，副屏可悬浮并随档位出帧

基线是 0.2.8（`versionCode 30`）装机后的真机读数：**应用一启动就死**，用户看到的是
「悬浮窗按钮使用后会闪退」。崩溃缓冲区里抓到的是：

```
FATAL EXCEPTION: main
Process: io.deepseekharness.mobile, PID: 26336
java.lang.RuntimeException: Unable to start service io.deepseekharness.mobile.OverlayBallService
  with Intent { xflg=0x4 cmp=io.deepseekharness.mobile/.OverlayBallService }
Caused by: android.view.InflateException: Binary XML file line #10 in
  io.deepseekharness.mobile:layout/view_overlay_ball: Error inflating class android.widget.FrameLayout
Caused by: java.lang.UnsupportedOperationException: Failed to resolve attribute at index 35:
  TypedValue{t=0x2/d=0x7f0400dd a=-1}, theme={…Theme.DeviceDefault.Light.DarkActionBar…forced}
    at android.content.res.TypedArray.getDrawableForDensity(TypedArray.java:1202)
    at io.deepseekharness.mobile.OverlayBallService.onStartCommand(SourceFile:228)
```

`aapt2 dump resources` 查出 `0x7f0400dd` 就是 `attr/selectableItemBackgroundBorderless`——一个
**AppCompat 属性**。布局里写着 `android:foreground="?attr/selectableItemBackgroundBorderless"`，
而厂商的「强制主题」开关会把服务上下文的主题换成平台主题 `Theme.DeviceDefault.*`，平台主题里没有
这个属性，`TypedArray.getDrawable` 直接抛 `UnsupportedOperationException`；异常从
`onStartCommand` 逃出，`Service` 启动失败即**终结整个应用进程**。悬浮球开关是开着的时候，
应用每次冷启动都会走这条路径，于是「一打开就闪退」。

## 改动

- **悬浮球布局不再依赖 AppCompat 属性**：`view_overlay_ball.xml` 改用平台属性
  `android:foreground="?android:attr/selectableItemBackgroundBorderless"`，它在平台主题与
  AppCompat 主题下都存在。
- **充气加主题包装与失败兜底**：`OverlayBallService.attachBall()` 改为用
  `ContextThemeWrapper(this, R.style.AppTheme)` 充气，并整段 `runCatching`；失败时记
  `phase=overlay|result=failed|reason=overlay_inflate_failed|active=false` + `Log.w("dsh-runtime", …)`
  后停服务返回，**不再把异常抛回 `onStartCommand`**——悬浮球画不出来最多是没有悬浮球，
  不能连累整个应用。这与既有的 `overlay_attach_failed` 处理方式一致。
- **短按与长按互换**：用户要的是「点悬浮球出菜单」。现在**短按主球展开二级菜单**，
  **长按主球直接展开同源 Harness 对话小窗**（原来的设计正好相反）。拖动移动球的行为不变。
- **二级菜单新增两个入口**：菜单顺序为「打开对话 / 打开副屏 / 回到应用 / 隐藏悬浮球 / 关闭无障碍」。
  「打开对话」进入既有的对话小窗；「打开副屏」调用既有的 `VirtualScreenService.showOverlay()`
  显示系统级副屏悬浮窗，副屏会话没在跑时提示「副屏尚未运行，请先在 Harness 里打开『目标应用副屏』」。
- **副屏悬浮窗加档位行**：悬浮窗工具条下面多一行四个按钮（省电 / 15 FPS / 30 FPS / 60 FPS），
  当前档高亮，点一下就走既有的 `config` 动作切档——不必「先展开成整页、改完档再收回来」。
- **关闭「静止页面复用」**：状态行不再写「静止页面复用最近一帧」，改为显示当前档位
  （`副屏预览 · <输入通道> · <实测帧率> · 档位 <档位>`）；预览的取帧间隔从固定 250 毫秒改成
  **随档位**（`VirtualScreenPolicy.previewPullInterval`：省电 180 毫秒，其余三档夹到 120 毫秒下限）。
  需要说清楚的是：档位决定的是**采集间隔**，也就是这副屏多久取一次画面；目标应用自己没有新画面时，
  取到的仍然是同一张图（这是 Android 虚拟显示的行为，不是应用在复用旧帧）。
- 版本号 0.2.8 → 0.2.9（`versionCode 31`）。
- 上一版内容见 [发布说明-0.2.8.md](发布说明-0.2.8.md)、[发布说明-0.2.7.md](发布说明-0.2.7.md)。

## 未解决的设备限制

- 悬浮球与副屏悬浮窗都要求「显示在其他应用上层」权限；权限被撤销时悬浮球会自行停用。
- 「打开副屏」需要一个已经在跑的副屏会话（目标应用由用户在副屏页面里选）；悬浮窗里的按钮
  只是切档位，不负责选择目标应用。
- 副屏相关限制与 0.2.8 相同：需要 Shizuku 授权与 Android 10 及以上；触摸直传
  （`touchChannel=stream`）依赖隐藏接口 `InputManager.injectInputEvent`，被 ROM 拦掉时回退到离散的
  `input -d <显示编号>`；节点树与中文注入要求用户手动开启应用的无障碍服务。
- 悬浮窗画面是 `FLAG_SECURE` 窗口的截图，因此系统截屏/录屏里看不到它也属预期。
