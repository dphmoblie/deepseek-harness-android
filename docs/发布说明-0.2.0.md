## 一、这一版修了什么（P0，按真机回执标注结论）

真机验收回执（2026-09-15 18:47，运行时于当日 18:38 更新重启后复测）逐条给了判定命令与证据：

| 条目 | 内容 | 真机结论 |
|---|---|---|
| P0-1 | 访客内 `link(2)` 被拒导致 `write` 工具无法新建文件 —— 用 pnpm 补丁给 `dsh-fs-local` 加 `rename` 回退 | ✅ **通过**（新建与覆盖均正常；`ln` 仍被拒属预期，根因未变） |
| P0-2 | 附件持久化全废（同根因）—— `rename` 回退 + 别名发布改用**复制**回退 | ✅ **通过**（`read_image` 返回 `attachmentId`/`bytes`，对象已落盘） |
| P0-4 | 访客 `/etc/hosts` 为空 → `localhost` 无法解析 —— 运行期生成并绑定 | ✅ **通过**（61 字节，含 `127.0.0.1 localhost`；proot argv 可见绑定） |
| P0-5 | 工作区不在保留白名单（升级即静默丢失）—— `workspace → root/1` 纳入保留 | ✅ **通过**（rootfs 重新解包后 `/root/1` 内旧文件仍在且 mtime 原样） |
| P0-6 | 密钥明文出现在 `proot` argv —— 取值移出 argv，改走 0600 文件与凭据文档 | ✅ **通过**（全进程扫描 argv 无命中；`runtime-secrets.env` 为 0600） |
| P0-3 | `workspace-write` 沙箱在本机不可用 | ⏸ **未验**（当前为 `danger-full-access`，未触发该分支） |

**P0-6 的人工动作仍未完成**：如果该 API Key 曾以明文进入 bugreport / 日志 / 分享内容，**应当轮换**——
代码只保证以后不再泄露，管不了已经出去的那把。

## 二、这一版加了什么（§5.x）

- **§5.1 存储权限分级**：设置页新增「共享目录」区块，用**用户显式选择的 ≤8 个目录白名单**取代
  `/sdcard` 整体绑定，访客内挂到 `/mnt/user/<序号>`；含 SAF 选择器、17 个受控错误码的中文说明、
  取消不算失败的处理。
- **§5.4 主题自定义**：三态（跟随系统/浅色/深色）+ 系统配色实时跟随；`styles.css` 令牌化并补深色一套
  （令牌块之外的硬编码颜色 66 → 0）；状态栏跟随应用主题（含 targetSdk 35 下 `statusBarColor`
  被忽略、必须靠图标明暗的适配）。
- **§5.5 任务通知**：独立通道 `dsh_tasks`，覆盖「Harness 自行退出」「安装/更新完成」
  「导出/导入完成」，未授予通知权限时静默不发，回到前台清除，**前台不发**。
- **§5.6 外壳优化**：首屏主包 396 KB → 253 KB（gzip −37%）、终端代码移出首屏；后台轮询真停表 +
  单飞；错误屏补「导出诊断日志」；测试拆成 6 个文件并可重复运行；字号全面 rem 化并接上
  `textZoom`（跟随系统字号）。
- **§5.6-H 运行时补丁**：运行时原本**不发任何缓存头**，导致控制台每次进入都全量重下——
  新增第 3 个 pnpm 补丁：入口 HTML `no-cache`、内容哈希资源 `immutable`。
- **登机（§5.3）**：外部「分享/打开」入口早已可用（本次核实并更正登记册），文件由 App 拷贝进收件箱。

## 三、已知问题（**交付前请务必读**）

1. **§5.7 内置网络工具链不可用（功能回归）**——真机实测 `curl` 报
   `error while loading shared libraries: libcurl.so.4`，`ssh` 报 `libgssapi_krb5.so.2`，
   `git ls-remote https://…` 因 `libcurl-gnutls.so.4` 失败。**二进制装了、运行库没装**。
   目前只有 `git` 的本地操作（init/add/commit）可用。修法很小（补 `libcurl4`/`libcurl-gnutls4`
   与 `libgssapi-krb5-2`，几 MB），**排在 0.2.0 之后的第一个修复批次**。
2. **`/usr/local/bin/python3`、`python` 是悬空符号链接**（构建脚本少写了一层 `../`）——
   PATH 上的 `python3` 不可用；预载脚本用绝对路径调起，因此掩盖了它。
3. **`screenshot` 工具报输出 schema 不匹配**（`value.image.mediaType` 不在允许集合内）——
   P0-2 修好后阻塞点前移，暴露出插件返回值与附件存储返回的 `mediaType` 不一致。
4. **Android 8–10 上访客内不再有共享存储**：白名单依赖「所有文件访问」（API 30+），
   而整体绑定已按设计移除。这是「用显式选择取代整体绑定」的必然代价，界面会如实说明。
5. **投递区需要 T2**：未授予「所有文件访问」时投递区显示不可用（这是预期降级，不是故障）。
6. **沙箱能力**：本机 `workspace-write` 不可用（ROM/内核限制），界面不会把它宣传为可用的安全能力。

## 四、升级注意

- **工作区与凭据会保留**（P0-5/P0-6 的改动已过真机验收）；更新对话框的文案已收窄：
  **在终端里用 `dsh plugin add` 装进运行时的插件不会保留**，更新后需重装。
- 首次启动后请到「运行与后台 → 共享目录」按需授权并选择目录；未授权时访客内没有共享存储。

## 五、验证口径（本发布说明的依据与边界）

- P0 各条的依据是**真机回执**（含可重跑的判定命令），不是代码走查。
- §5.x 的依据是**本机自动化测试**：前端 25 文件 / 299 用例、契约 `node --test` 105/105、
  Kotlin 48 类 / 351 用例、`eslint` 与 `tsc` 干净、`:app:lintRelease` 通过。
- **§5.x 的功能没有做过真机验收**（本节列出的真机结论只覆盖 P0 各条）；
  §5.1 的 SAF 与 `/mnt/user/<n>`、§5.5 的通知、§5.6-H 的缓存命中都需要真机复核。
- 本发布**不包含** §5.8–§5.13 建议（工作区文件操作增强、同步策略、启动优化、其它优化清单、
  外壳内文件管理、对话「从工作区选择」）——那些是下一阶段的方向。
