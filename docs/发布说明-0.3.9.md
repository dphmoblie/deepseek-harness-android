# 0.3.9 发布说明

## 内置插件市场（第三方）

- rootfs 现在自带 `dshmarket` 1.73.14：它作为**第三方插件**写进移动 profile 的
  `dsh.profile.bundles`（排在官方 bundle 之后），并由构建脚本生成
  `root/.dsh/profiles/node_modules/dshmarket` 的扁平链接。装好运行时后，Harness 的「插件」页
  直接就有插件市场，不需要先联网安装。
- 版本钉在 `scripts/runtime-profile/package.json` 与 `pnpm-lock.yaml`，与镜像同一份流水线构建。
  CI 在 ARM64 rootfs 作业里用与镜像同构的 Node 实际 `import('dshmarket')`：它的入口静态
  import 了可选 peer `@deepseek-ai/schemastery`，缺链时插件加载失败，所以这一条是构建门禁，
  不是提示。
- 插件管理页按既有规则把它当第三方插件（非 `@deepseek-ai/` 前缀），可启停；账本里没有事务
  目录，升级迁移不会误报“需要重新安装”。APK 的 legal 资产同步收录它的 MIT 许可证文本，
  `THIRD_PARTY_NOTICES.md` 增加一行说明。
- 版本随镜像走：应用内切换到某个上游 npm Harness 版本后，那棵树里没有这个包，dsh 会按
  skipped bundle 机制跳过并在终端提示；切回内置运行时即恢复。

## 旧版 WebView 兼容（Android 10–17）

- 副屏设置的「屏幕方向」与「自动跟随」不再依赖 CSS `:has()`（Chrome 105+ 才有）：
  选中态改由 React 显式写 `.virtual-screen-choice.is-selected`。旧 WebView 不会再把整条
  规则连同高亮一起丢掉。
- 所有 `dvh` 视口单位（Chrome 108+）前补同属性的 `vh` 兜底：启动页、应用外壳、语言页、
  工作区弹窗、对话框与应用选择列表在旧引擎上仍有正确高度，不再整条 `height` / `max-height`
  失效。
- 新增 CSS 门禁：`src/legacyWebViewCss.test.ts` 现在同时拦截 `:has()` 和「有 `dvh` 没有
  `vh` 兜底」；副屏选中态另有组件测试钉住显式类名，防止以后改回纯 CSS 选择器。

## 随包运行时复核

- 按 Release 资产重新核对 `rootfs.bundle`：`checksums.txt`、`runtime-manifest.json` 与归档
  SHA-256 三者一致（407,863,855 字节，`0.3.9-mobile-605`），解包 38,702 个成员无损坏。
- rootfs 内 866 个 ARM64 ELF 的 `PT_LOAD` 对齐全部是 64 KB（`p_align=0x10000`），
  没有低于 16 KB 的对象；APK 的 3 个 `lib/arm64-v8a/*.so` 也通过 16 KB 对齐校验。
  Android 15 / 16 / 17 的 16 KB 页设备可直接加载。
- 运行时由 CI 重新打包为 `0.3.9-mobile-605`（`dshVersion` 仍为 `0.2.1-rc.1`）；
  APK 内置 bundle 与 Release 附件的摘要一致。

  `node --test scripts/*.test.mjs` 361 项 / 357 通过 / 4 跳过 / 0 失败。

  （163 类 / 1588 例 / 0 失败 / 0 错误 / 37 跳过）。

## 已知限制

- Harness 页面（上游前端 + `harness-web/android.css`）仍用 `:has()` 做抽屉布局：
  低于 Chrome 105 的 WebView 会整块回退到官方三列布局，侧栏保持轨道，不会比现在更差。
- 上游前端仍用到 `Object.hasOwn`（Chrome 93+）、`.at()`（Chrome 92+）等 ES2022 级 API，
  属于当前构建基线（`target: es2022`）；低于该基线的 WebView 不在支持范围。
