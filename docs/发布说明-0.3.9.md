# 0.3.9 发布说明

## 旧版 WebView 兼容（Android 10–17）

- 副屏设置的「屏幕方向」与「自动跟随」不再依赖 CSS `:has()`（Chrome 105+ 才有）：
  选中态改由 React 显式写 `.virtual-screen-choice.is-selected`。旧 WebView 不会再把整条
  规则连同高亮一起丢掉。
- 所有 `dvh` 视口单位（Chrome 108+）前补同属性的 `vh` 兜底：启动页、应用外壳、语言页、
  工作区弹窗、对话框与应用选择列表在旧引擎上仍有正确高度，不再整条 `height` / `max-height`
  失效。
- 新增 CSS 门禁：`src/legacyWebViewCss.test.ts` 现在同时拦截 `:has()` 和「有 `dvh` 没有
  `vh` 兜底」；副屏选中态另有组件测试钉住显式类名，防止以后改回纯 CSS 选择器。

## 随包运行时复核

- 重新核对 APK 内的 `rootfs.bundle`：SHA-256 与 `runtime-manifest.json` 一致
  （407,859,454 字节），归档可完整解压。
- rootfs 内 866 个 ARM64 ELF 的 `PT_LOAD` 对齐全部是 64 KB（`p_align=0x10000`），
  没有低于 16 KB 的对象；APK 的 `lib/arm64-v8a/*.so` 也通过 16 KB 对齐校验。
  Android 15 / 16 / 17 的 16 KB 页设备可直接加载。
- 本轮不重打运行时：只改了 APK 侧前端资产，`rootfs.bundle` 内容未变。

## 验证

- 前端：`tsc -b`、`eslint . --max-warnings 0`、`vitest run` 73 文件 / 989 例全过；
  `node --test scripts/*.test.mjs` 358 项 / 354 通过 / 4 跳过 / 0 失败。
- 原生：`:app:compileDebugUnitTestKotlin` 与 `:app:testDebugUnitTest` 通过
  （162 类 / 1585 例 / 0 失败 / 0 错误 / 37 跳过）。
- CI 重新构建 Debug / Release 测试 APK，并执行内置 bundle 完整性与 16 KB 对齐校验。

## 已知限制

- Harness 页面（上游前端 + `harness-web/android.css`）仍用 `:has()` 做抽屉布局：
  低于 Chrome 105 的 WebView 会整块回退到官方三列布局，侧栏保持轨道，不会比现在更差。
- 上游前端仍用到 `Object.hasOwn`（Chrome 93+）、`.at()`（Chrome 92+）等 ES2022 级 API，
  属于当前构建基线（`target: es2022`）；低于该基线的 WebView 不在支持范围。
