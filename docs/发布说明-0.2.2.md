## 二、本版相对上一个预览版 `v0.2.2-mobile-316` 新增（本轮工作）

### 1. 插件：受控导入入口

`import(source, id?)` 支持三种来源（npm 包名 / `https://` 直链 tarball / `git+https://…#ref`），
源码、桥接与 TypeScript 平台层**三处同源规则**：长度与字符白名单、拒绝 `http://`/`git://`/`ssh://`/
`file:`/`data:`、拒绝 `..`（含 `%2e`）与前导 `-`；**失败一律受控码、不回显用户输入**。
安装脚本恒不执行（`--ignore-scripts`），导入与更新共用同一条事务路径，重复导入幂等。

### 2. 插件：数据保留、跨运行时升级的状态迁移与版本回滚

插件包内可变数据目录在更新时先完整搬进暂存版本再切链（**不跟随符号链接**，越界即
`PLUGIN_DATA_UNSAFE`/`PLUGIN_DATA_TOO_LARGE` 放弃本次更新且**旧版本完好**）；启停状态写入保留目录并
按清单指纹回填（**已有选择绝不覆盖**）；每次成功更新前的那一版登记为「上一版」，界面可
**回滚到上一版本**，回滚走同一套事务、可再回滚。

### 3. C 编译环境＝能力探测，不是承诺

运行时自检新增 `c_compiler`/`make`/`python3` 三项（**追加在 `rg` 之后**，前 11 项 id 与顺序冻结），
三项一律 `warn`、不参与失败判定；`c_compiler` 的 `ok` **必须真做一次最小编译+链接**（有超时、
只读、**不装任何东西**）。安装引导页据此加了「运行时包里不带 C 编译器」的如实说明。

### 4. 任务完成回对话 + 锁屏可见通知

访客插件新增 `lib/turn-signal.js`：用 `ctx.on('session/event')` 捕获 `turn/end`，
2 秒 best-effort 上报（内建命令、**不建 Shell 会话**、参数只认三个键且上限 96 字符）；
原生只在**真正受理**时推进序号，外壳 5 秒轮询读到序号变大且当前不在对话页就切回对话界面。
完成通知使用**独立通知 id**（与操作类通知分开，并修掉与悬浮球前台服务通知**同号互相覆盖**的既有缺陷）、
点击走 `KeepAliveEntryActivity`、每条 `setVisibility(VISIBILITY_PUBLIC)` 让锁屏可见；
**全仓仍无 `setFullScreenIntent`**（不抢全屏）。

### 5. 悬浮球二级菜单与可缩放小窗

文字长按菜单换成**二级悬浮球按钮组**（回到应用 / 隐藏悬浮球 / 关闭无障碍，命中区 ≥40dp、
贴边夹取、跟随主球）；「关闭无障碍」用 `AccessibilityService.disableSelf()`，只在本进程当前持有该服务时
有效，**不承诺「调用一定会关掉」**。小窗支持拖 ◢ 手柄改尺寸（240×360dp 下限、屏高/宽九成上限），
尺寸持久化，横竖屏/分屏后重新夹取到合法范围。

### 6. 运行时句柄竞态（真机日志暴露的缺陷，本版修掉）

- **症状**：0.2.2 预览版的真机日志里出现 `APP_DESTROY|result=failed|active=false`，
  紧接**连续三条** `HARNESS_START|result=failed|code=RUNTIME_CLOSED`，且此前的
  `DEVICE_BRIDGE|result=reused` 说明进程级设备桥并未重建——即插件实例手里的控制器已被关闭，
  但引用还挂在宿主上（僵尸句柄）。
- **根因**：`shouldReleaseRuntimeOnPluginDetach()` 只看「前台服务是否在负责」，
  **不看还有没有别的订阅者**；保活关闭时旧插件实例收尾会把新实例正在使用的运行时关掉。
  另外 `takeControllerLocked()` 先清理后置空引用，清理中途抛错就会留下「已关闭但仍被登记」的控制器。
- **修法**：释放条件加上「无其他订阅者」，并让 `takeControllerLocked()` **先摘引用再清理**
  （清理步骤仍如实抛出，保留 `APP_DESTROY|result=failed` 诊断信号，但下一次 `acquire()` 会新建运行时）；
  前端对 `RUNTIME_CLOSED` 给出「需要重新连接」的明确文案，并至多自动重连一次。
- **验证**：本机 Kotlin 单测（`HarnessKeepAlivePolicyTest` 新增「仍有其他订阅者时必须保留」）与
  前端用例（首次失败 → 重连成功 / 两次都失败 → 明确提示 / 其它错误码不重试）；
  **真机复现步骤见验收清单 K19、K20**，本轮**未做真机复测**。

## 三、已知问题与边界（务必先读）

1. **本轮功能没有真机验收**：插件的网络安装（真实 registry / tarball / git clone）、
   `disableSelf()` 在厂商 ROM 上的效果、「锁屏可见」在**升级安装**下的表现、真实设备上 dsh 是否每轮都
   产生 `turn/end`——这些只能真机确认，逐条判据在 `docs/mobile-acceptance-checklist.md` 第 17 节（二十条）
   与 §5.1 的 K19/K20。
2. **C 编译环境只是如实上报能力**：apt 在包内，但**能否联网取包未经验证**；自检的 `warn` 不是失败。
3. **不使用 Shizuku 作为 root 或永久保活手段**，也不承诺绝对防止被系统杀死；进程被强制停止后
   旧认证会话可能无法恢复，界面会提示需要重新连接。
4. 沿用 0.2.0 的既有边界：Android 8–10 上访客内没有共享存储（白名单依赖 API 30+ 的
   「所有文件访问」）；未授予时**投递区显示不可用**属预期降级；本机 `workspace-write` 沙箱不可用
   （ROM/内核限制），界面不把它宣传为可用的安全能力。

## 四、升级注意

- `versionCode` 仍是 **24**，与上一个预览版 `v0.2.2-mobile-316` 相同 ⇒ 同一签名的 APK 可直接**覆盖安装**，
  不需要先卸载。
- 工作区、凭据、插件（含插件数据）在更新后保留；从 `v0.2.0` 直接升到本版会先经历 0.2.1 的
  **安装前会话快照**，再走 0.2.2 的**会话格式 v3 → v4 迁移**。
- 在终端里用 `dsh plugin add` 装进运行时的插件不属于受管插件，更新后需重装（界面已如实说明）。

## 五、验证口径（本发布说明的依据与边界）

- 依据是**本机自动化测试**（提交前最后一次串行运行的真实数字）：
  `npx tsc -b` 与 `npx eslint . --max-warnings 0` 均 exit 0；
  `npx vitest run` = **33 文件 / 429 用例全绿**；
  `node --test scripts/*.test.mjs` = **156 例 / 152 过 / 0 挂 / 4 跳过**（跳过的是 2 条会话格式写路径
  用例——Windows 缺 koffi 原生绑定，与 2 条 POSIX 专用编译器用例）；
  `:app:testDebugUnitTest --rerun` = **64 类 / 505 测试 / 0 失败 / 15 跳过**；
  `:app:lintRelease --rerun` = **0 错误 / 38 警告**（全部为 Warning 级，CI 门禁只看 error）。
- **没有真机验收**：本发布说明不声称任何一项功能已在真机上通过；真机结论以验收清单的回执为准。
- CI 侧：推送 `main` 只做构建与验证；正式版与预览版都由 `workflow_dispatch` 的
  `release_type` 决定，正式版标签为 `v${APP_VERSION}`。
