# 自动化工作流：录制、编译与回放设计

> **状态**：设计稿（2026-11-08），**未实现**。本文定义模型、接口、状态机、边界与测试计划，不含实现代码。
> **范围**：用户在主屏示范一次操作 → 本地编译成工作流 → 可选 AI 编导 → 用户确认 → 原生确定性回放；AI 只在录制后审阅与卡住时兜底。
> **约定**：
> - 【码】= 现有代码里已存在，给出 `文件:行号` 或符号名。
> - 【推】= 本文的设计，尚未实现。
> - 【验】= 需要真机或设备测试才能确认，本文不下结论。
> - 所有行号以本文写作时的 checkout 为准，并行改动可能让行号偏移。

## 0. 一句话

**用户示范一遍，系统把它编译成一份可读、可编辑、可校验的工作流；执行时由原生无障碍服务按同一份工作流确定性回放，正常路径不调用 AI。AI 只在两处出现：录制后的一次性编导建议，以及卡住时的补救。**

这条线与现有「规则」的分工：

| | 现有 `AutomationRule` | 本文的工作流 |
| --- | --- | --- |
| 触发 | 界面事件满足条件就执行一条动作 | 用户点「运行」，按节点顺序执行 |
| 表达 | 单步：看到什么点什么 | 多步：动作、条件、断言、成功/失败分支 |
| 编写者 | 目前主要是 AI | 用户录制；可选 AI 编导 |
| 运行依赖 AI | 规则求值不依赖，但规则内容由 AI 写 | 不依赖；AI 只提建议 |
| 状态 | 每条规则独立计数 | 一次运行一份路径与现场单 |

> 两者**共存**，不合并。规则继续负责「界面上出现 X 就点 Y」的事件驱动场景；工作流负责「把一件事从头做到尾」的按需场景。共用选择器、节点执行后端、白名单/锁屏/敏感窗口/频率闸门。

## 1. 问题与目标

### 1.1 现状

- 现有自动化参数（`AutomationRule`、`AccessibilityAppConfigStore`）是**单步规则**模型：选择器 + 一个动作 + 次数/冷却/重置。用户能在界面上改规则参数，但**没有「录一遍」的入口**，也没有「一串有序动作」的模型。
- `AutomationTaskLedger` 有步骤状态、重试、目标过期等语义，但它是 **AI 下发计划、逐步提交** 的台账；动作仍由 AI 逐步发命令，不是本地回放。
- 因此当前闭环是「AI 观察 → AI 写参数/发动作 → AI 验证」，用户既难记录自己的操作，执行也依赖 AI。

### 1.2 目标

1. **可记录**：用户在主屏操作一遍，系统录下动作、目标、时序与前后界面，形成可读轨迹。
2. **可控制**：编译出的每个参数都可见、可改、可回退；AI 不能静默改参数。
3. **可独立运行**：AI 完全不在线时，录制 → 编译 → 回放仍能跑通。
4. **可验证**：每步有目标与期望；失败就暂停并给现场单，不猜、不盲目重试。
5. **AI 只做增强**：录制后一次性编导（可选）、卡住时补救（优先直接处置，其次改参数，最后中止）。
6. **为前后台留缝**：V1 只做主屏；模型与执行器留 `surface`，以后接副屏/虚拟显示。

### 1.3 非目标（V1）

- 不做循环（「滚动直到找到」）、并行、定时触发、应用启动触发。
- 不做副屏/后台 surface；只留字段与接口。
- 不做应用内自动调用模型；AI 交互走 Harness 对话 + 工具。
- 不自动开通自动化总开关；不放开白名单/敏感页/频率。
- 不保存密码、验证码、支付信息；输入内容默认不存字面量。
- 不替代现有规则系统。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 轨迹（trace） | 录制产生的事件序列与每步的节点/屏幕快照；只在本机。 |
| 工作流（workflow） | 节点 + 边的有向无环图；可执行、可编辑、可校验。 |
| 草稿（draft） | 本地编译器从轨迹生成的第一版工作流；不需要 AI。 |
| 编导计划（plan） | AI 对草稿提出的剪辑/标注/参数/guard 变更；不直接生效。 |
| 提案（proposal） | 计划编译后的候选 revision + diff；等待用户接受。 |
| revision | 工作流的一次冻结版本；运行只认一个 revision。 |
| 现场单（incident） | 运行暂停时的结构化事实：节点、失败码、路径、耗时、当前界面指纹。 |
| surface | 操作面：V1 只有 `main`（主屏前台）；以后可有 `display:<id>`。 |
| guard | 条件节点：按观察到的界面事实选择分支，不新增动作。 |

## 3. 总体架构

```text
用户操作（主屏）
  │  TYPE_VIEW_CLICKED / LONG_CLICKED / TEXT_CHANGED / SCROLLED / WINDOW_STATE_CHANGED
  ▼
录制器（服务内，纯状态机） ──► 轨迹 trace（本机）
                                  │
                                  ▼
                         本地编译器（纯逻辑）
                                  │
                                  ▼
                         草稿 workflow（可运行）
                                  │
                    ┌─────────────┴─────────────┐
                    │                           │
                    ▼                           ▼
             用户直接编辑                   AI 编导（可选）
                    │                    读轨迹 + 草稿 → 计划
                    │                           │
                    │                    编译成候选 revision + diff
                    │                           │
                    └─────────────┬─────────────┘
                                  ▼
                         用户确认 / 拒绝 / 回退
                                  ▼
                         冻结 revision（唯一可执行版本）
                                  ▼
                    原生运行器（无 AI）按图执行
                                  ▼
                     成功 / 暂停 + 现场单 / 中止
                                  │
                                  ▼
                    用户或 AI 决定：重试 / 跳过 / 改参数 / 中止
```

### 3.2 与现有代码的复用

- 选择器字段与严格 JSON 解析：复用 `AutomationRule.kt` 的 `Selector` 与 `AutomationRuleLimits` 口径【码】。
- 选择器匹配：把 `AutomationRuleMatcher` 里私有的 `matches(selector, node)` 抽成共享的 `AutomationSelectorMatcher`，规则与工作流共用【推】。抽取时保持逐字段语义不变。
- 节点动作：复用 `AutomationNodeBackend`（click / clickCenter / longClick / back / swipe / key / launch）与 `BackendOutcome`【码】`AutomationRuleExecutor.kt:509-567`。
- 文本写入：复用服务侧 `writeTextOnDisplay` / `injectTextOnDisplay` 的既定闸门与失败码【码】`DeepSeekAccessibilityService.kt:641-957`。
- 窗口指纹：复用 `AutomationWindowDigest`（不含文本、对结构敏感）【码】。
- 运行记录：复用 `AutomationRunHistory` 的环形缓冲思路，新增工作流运行记录；不把界面文本写进记录【码】`AutomationRunLog.kt`。
- 安全闸门：白名单 `AccessibilityAutomationStore.packageAllowed`、锁屏 `isLockedOrScreenOff`、敏感窗口 `containsSensitiveWindow`、频率 `ACTION_INTERVAL_MS`【码】。
- 总开关：沿用 `AutomationControlPolicy`（`off` / `running` / `paused`）【码】。录制不需要打开总开关；**运行需要 `running`**。

## 4. 工作流模型

### 4.1 图

- 单入口 `start`，至少一个 `end`；`pause` 可选。
- 有向无环图（DAG）；允许多条边汇合到同一节点（单 token，先到先继续）。
- 节点 id：`n1`..`n40`（`^[a-z][a-z0-9-]{0,15}$`，可用 `end-ok` 这类短横线名）；`pause` 节点固定 id `pause`（V1 只有一个）。
- 边按来源节点的字段名区分，不用独立边数组：`next`、`onSuccess`、`onFailure`、`onTrue`、`onFalse`、`onSkip`。这样 JSON 更短，校验器按节点类型检查必填边。

### 4.2 节点类型

| 类型 | 必填字段 | 可选字段 | 出边 |
| --- | --- | --- | --- |
| `start` | `packageName` | `activityName`、`launch`（布尔） | `next` |
| `action` | `action`；`selectors`（click/longClick/setText 必填；scroll 可选） | `value`、`waitBeforeMs`、`timeoutMs`、`settleMs`、`retries`、`optional`、`risk`、`expect` | `onSuccess`、`onFailure`、`onSkip`（`optional=true` 时必填） |
| `condition` | `predicate` | `settleMs` | `onTrue`、`onFalse` |
| `assert` | `predicate` | `timeoutMs`、`settleMs` | `onSuccess`、`onFailure` |
| `end` | `result`（`success` / `failure` / `cancelled`） | `message` | 无 |
| `pause` | — | `reason` | 无 |

### 4.3 动作

`action.type` 取值：

| 类型 | 附加字段 | 语义 |
| --- | --- | --- |
| `click` | — | 点节点；不可点击时按「最近可点击祖先 → 中心坐标」降级，与规则执行器一致 |
| `longClick` | — | 长按节点 |
| `scroll` | `direction`（up/down/left/right） | 滚动；有选择器时滚目标容器，没有时从屏幕中心做一次 swipe |
| `setText` | `value` | 写入聚焦的可编辑节点；走既有文本写入链 |
| `back` | — | 全局返回 |
| `wait` | `delayMs`（1..10000） | 只等待，不碰界面 |

> 复用 `AutomationRule.kt` 的动作字段语义与按键表；`launch` 在 V1 工作流里**不开放**（工作流从目标应用已在前台开始）。需要启动应用时，由 `start.launch=true` 在运行前调用既有 `mobile_device_app_launch` 的同一口径启动目标包，不放进节点动作【推】。`start.launch` 只接受目标包名，不接受任意 component/uri。

### 4.4 选择器

- 字段与 `Selector` 完全一致【码】`AutomationRule.kt:101-188`。
- 需要目标节点的动作（click / longClick / setText）配 1..3 个选择器，按顺序尝试；任一命中即用。列表语义是 OR。`scroll` 可选选择器；`back`/`wait` 不需要选择器。
- 录制默认只生成 1 个；AI/用户可加候选。
- 选择器字段之间 AND；空选择器拒绝。
- `id` 仍只接受全写 `包名:id/名称` 或短写 `:id/名称`；短写在跨包场景有歧义，录制默认写全写。

### 4.5 条件与断言

`predicate` 取值（V1）：

| 类型 | 字段 | 判定 |
| --- | --- | --- |
| `nodeExists` | `selectors` | 当前窗口里存在任一命中节点 |
| `textVisible` | `text` | 非可编辑节点的可见文本里存在精确相等或包含（`contains` 布尔） |
| `activityIs` | `activityName` | 当前前台 Activity 精确相等 |
| `packageIs` | `packageName` | 当前前台包名精确相等 |

- `condition` 是**立即**求值：看当前快照，选择 `onTrue`/`onFalse`；不等。
- `assert` 是**等待**求值：在 `timeoutMs` 内反复轮询，直到成立；超时走 `onFailure`。
- 两者都带 `settleMs`（默认 300ms）：谓词必须连续成立 `settleMs` 才认为稳定，避免动画/加载中误判。`activityIs`/`packageIs` 不做 settle。
- 谓词只读，不执行动作；不读输入框内容；密码/敏感页在求值前已由服务闸门拒绝。

**动作后的 `expect`**（与 `condition` 的谓词分开，因为它带「动作前」基线）：

| `expect.kind` | 字段 | 判定 |
| --- | --- | --- |
| `none` | — | 不验证（界面标「未验证」） |
| `screenChanged` | — | 当前结构指纹与动作前不同 |
| `nodeGone` | `selectors` | 动作前命中的目标节点不再存在 |
| `textAppears` | `text`、`contains` | 动作前没有、动作后出现该文本（非可编辑节点） |
| `activityChanged` | `activityName` | 当前前台 Activity 变为指定值 |

- `expect` 在 `timeoutMs` 内等待，并同样要求连续成立 `settleMs`。
- `screenChanged` 用结构指纹，不读文本；`textAppears` 只读非可编辑节点，密码/输入框内容不参与。

### 4.6 控制流语义

- **动作节点**：等待目标出现（`timeoutMs`）→ 执行动作 → 若配置 `expect`，在 `timeoutMs` 内等待期望成立 → 走 `onSuccess`；任何一步失败走 `onFailure`。
- **可选动作**：目标在 `timeoutMs` 内没出现 → 走 `onSkip`，不记失败；动作已执行但期望未达成 → 仍是失败（不能把「点了没效果」当跳过）。
- **条件节点**：立即求值 → 真/假。
- **断言节点**：等待谓词成立 → 成功/超时。
- **汇合**：多条边指向同一节点时，先到先继续；不等待其它分支，不做同步。
- **失败边**：默认指向 `pause`；用户可改到某个 `end`（例如「失败也停止」）或另一个动作节点（有风险，需确认）。
- **无环**：运行器不处理回边；校验器直接拒绝环。

### 4.7 校验规则（V1）

1. `entry` 必须指向一个 `start` 节点；有且只有一个 `start`。
2. 所有节点从 `start` 可达；不存在孤立节点。
3. 无环（DFS 三色标记）。
4. 每个节点的必填出边存在且目标存在；`action.optional=true` 时 `onSkip` 必填；`condition` 必须有 `onTrue` 与 `onFalse`。
5. 至少一个 `end`；`pause` 可有可无，但失败边默认指它。
6. 所有路径最终能到 `end` 或 `pause`（不允许死胡同）。
7. 节点数 ≤40，边数 ≤80，最长路径 ≤30。
8. 需要目标节点的动作（click / longClick / setText）必须有 1..3 个选择器，每个选择器非空；`scroll` 可有 0..3 个；`back`/`wait` 不允许带选择器。
9. `setText` 必须带 `value`；其它动作不带 `value`。
10. `scroll` 必须带 `direction`；`wait` 必须带 `delayMs` 且 1..10000。
11. `risk=true` 的节点 `retries` 必须为 0。
12. `surface` 必须是 `main`（V1）；非 main 整体拒绝。
13. 未知字段、类型不符、越界一律整体拒绝，不截断、不取默认值。
14. `condition`/`assert` 的 `predicate` 字段必须与 `kind` 配套：`nodeExists` 的 `selectors` 1..3；`textVisible` 的 `text` 非空；`activityIs`/`packageIs` 的值合法且非空。
15. `end.result` 只能是 `success` / `failure` / `cancelled`。

错误码统一 `AUTOMATION_WORKFLOW_INVALID`，消息里指出具体节点/字段。

## 5. 录制

### 5.1 事件与快照

录制依赖无障碍事件。现有订阅只有 `TYPE_WINDOW_STATE_CHANGED | TYPE_WINDOW_CONTENT_CHANGED | TYPE_VIEW_SCROLLED`【码】`res/xml/accessibility_service_config.xml`、`DeepSeekAccessibilityService.kt`。录制需要额外事件：

| 事件 | 用途 | 备注 |
| --- | --- | --- |
| `TYPE_VIEW_CLICKED` | 用户点击 | `event.source` 是点击的 view |
| `TYPE_VIEW_LONG_CLICKED` | 长按 | 部分 ROM 不派发【验】 |
| `TYPE_VIEW_TEXT_CHANGED` | 输入 | 每字符一次；按节点合并 |
| `TYPE_VIEW_SCROLLED` | 滚动 | `getScrollDelta()` 方向 |
| `TYPE_WINDOW_STATE_CHANGED` | 界面切换 | 不产生步骤，产生屏幕标记 |
| `TYPE_WINDOW_CONTENT_CHANGED` | 内容变化 | 只做屏幕摘要刷新，不产生步骤 |

**事件类型的开启方式**：优先在录制开始时通过 `AccessibilityServiceInfo` + `setServiceInfo` 临时加上四类事件，停止后恢复 XML 里的三类；避免常驻增加事件量。若运行时切换在某些 ROM 上不生效【验】，退回「XML 常驻全部类型 + 录制外早退」。V1 实现按临时切换，真机验证后再定。

**每步快照**：

- 动作：`click` / `longClick` / `scroll` / `setText`。
- 目标节点：`viewId`、`className`、`text`、`contentDescription`、`bounds`、`clickable`、`editable`、`scrollable`、`password`。
- 屏幕：`packageName`、`activityName`（能取到时）、`windowId`、结构指纹（`AutomationWindowDigest`）。
- 时间：`eventTime`、与上一步的间隔。
- 屏幕摘要：最多 20 个可见标签（去重、≤40 字符、排除可编辑/密码节点），供编译与 AI 审阅使用。
- `displayId`：API 30+ 读取；V1 只接受 `0`（主屏），其它 display 的事件直接忽略。

**自己产生的事件**：录制期间禁止运行工作流/AI 动作；若 500ms 内刚有自动化动作，丢弃该事件。事件包名必须等于目标包名；排除 `android`、`com.android.systemui` 与本应用包名。

**取不到 source 时**：`event.source` 可能为 null。回退顺序：
1. `rootInActiveWindow` 按事件时间猜最近的可点击节点并不可靠，V1 不猜。
2. 直接丢弃该事件，并计入 `missingSource` 计数；编译时如果 missingSource 超过 30%，提示「这个界面录不了」。
不做坐标猜测，避免录出无法回放的点。

### 5.2 录制状态机

```text
IDLE
  → ARMING（设置事件类型，1.5s 倒计时）
  → RECORDING（接收事件；上限 5 分钟 / 200 原始事件 / 40 步）
  → STOPPING（恢复事件类型，冻结轨迹）
  → COMPILING（本地编译）
  → DRAFT_READY（草稿）
  ↘ FAILED（服务断开 / 目标包不在白名单 / 存储失败 / 事件不足）
```

- 开始条件：无障碍服务已连接、目标包已白名单、没有运行中的工作流、没有正在录制。
- 停止条件：用户点通知/悬浮球、返回本应用、5 分钟超时、服务断开、步数上限。
- 录制过程中不写盘；停止后把轨迹与草稿**一次性**落盘（轨迹可单独删除）。原始轨迹按需保留（供 AI 审阅/重编译），默认保留到用户删除流程。
- 录制期间总开关可以不是 `running`（录制是只读的）；运行才要求 `running`。

### 5.3 轨迹格式

```json
{
  "schema": 1,
  "workflowId": "wf-5f2c1a9e",
  "packageName": "com.example.app",
  "recordedAt": "2026-11-08T14:00:00+08:00",
  "durationMs": 18320,
  "displayId": 0,
  "sharingLevel": "labels",
  "events": [
    {
      "seq": 0,
      "atMs": 0,
      "type": "click",
      "node": {
        "viewId": "com.example.app:id/skip",
        "className": "android.widget.TextView",
        "text": "跳过",
        "desc": null,
        "bounds": [980, 120, 1120, 190],
        "clickable": true,
        "editable": false,
        "scrollable": false,
        "password": false
      },
      "screen": {
        "activity": "com.example.app/.SplashActivity",
        "windowId": 12,
        "digest": "a1b2c3d4e5f60718"
      },
      "screenLabels": ["跳过", "广告", "进入应用"]
    }
  ],
  "screenMarks": [
    { "atMs": 3200, "activity": "com.example.app/.MainActivity", "digest": "..." }
  ]
}
```

- 轨迹只存本机；不写日志、不进审计、不上传。
- 文本按 `sharingLevel` 决定是否给 AI；本地始终保留（编译需要），用户可一键删除轨迹。
- 输入内容：**不存字面量**，只存 `textLength` 与 `masked=true`；`setText` 步骤默认 `value.mode="ask"`。
- 密码字段：服务本来就把 `isEditable` 节点的文本置空【码】`DeepSeekAccessibilityService.kt:148-170`；录制侧再拒一次。

### 5.4 隐私级别

| 级别 | 给 AI 的内容 | 默认 |
| --- | --- | --- |
| `none` | 只有 viewId/class/动作/时序/结构；无任何文字 |  |
| `labels` | 被点节点的文字 + Activity + 最多 10 个屏幕标签 | ✔ |
| `full` | 所有屏幕摘要标签 |  |

- 发送前展示将发送的 JSON 预览；用户可逐项取消。
- 密码/验证码/支付窗口不采集（服务侧已拒绝）；输入框内容永不进轨迹。
- AI 返回的计划只存在本机；不把计划正文写进日志。

### 5.5 录制 UX

- 入口：设置 → 自动化 → 目标应用 → 「录制工作流」。
- 点击后 3 秒倒计时，提示「现在切到目标应用，按你要自动化的步骤操作一遍」。
- 录制中：常驻通知「正在录制 · N 步」+「停止」动作；已有悬浮球时可在球菜单加「停止录制」。
- 返回本应用或点停止 → 立即编译 → 打开工作流预览，显示步数、可选步骤、低置信步骤。
- 事件不足/丢 source 过多 → 明确提示，不生成「看起来能跑」的流程。

### 5.6 已知限制

- WebView / Flutter / 游戏可能不派发可用的 `TYPE_VIEW_CLICKED`；录到的步骤会很少【验】。
- 系统返回手势、音量键、通知栏操作不可见；用户可手动加 `back`/`wait` 节点。
- 动态文案（数字、日期、昵称）会让 `text` 选择器不稳定；编译标记低置信，建议改用 viewId。
- 录制期间用户切到别的应用：只记录目标包名的事件，其它包忽略；切回继续。
- 屏幕旋转：`bounds` 变化；优先 viewId/text，不依赖坐标。

## 6. 编译

### 6.1 本地编译（不需要 AI）

输入：轨迹 + 目标包名。输出：草稿工作流 + 警告列表。

步骤：

1. **合并原始事件**
   - 同节点 300ms 内重复 `click` 合并为一次。
   - 连续 `textChanged`（同节点、间隔 ≤2s）合并为一个 `setText` 步骤。
   - 连续同方向 `scroll`（间隔 ≤1s）合并为一个 `scroll`，记录次数到 `note`（V1 不循环，只执行一次）。
   - `WINDOW_STATE_CHANGED` 转为屏幕标记，不生成步骤。
2. **生成动作节点**（线性链）
   - 每个合并后的事件一个 `action` 节点。
   - 选择器按 6.2 生成。
   - `waitBeforeMs`、`timeoutMs` 按 6.3。
   - `expect` 按 6.4。
   - `optional`、`risk` 按 6.5。
3. **连接**
   - `start.next` → 第一个动作。
   - 每个动作 `onSuccess` → 下一个；最后一个 `onSuccess` → `end-ok`。
   - `onFailure` → `pause`。
   - 可选节点 `onSkip` → 下一个。
4. **命名**
   - `<应用名> · <首个有意义的被点文字>`；没有文字时 `<应用名> · MM-dd HH:mm`。
   - 应用名从 `InstalledApplications` 取；取不到用包名。
5. **标记**
   - `needsReview`：没有稳定选择器、文本疑似动态、事件间隔异常、丢 source。
   - `lowConfidence`：只有 className+bounds、或文本长度 >40、或含 4 位以上数字。
6. **输出**
   - `traceHash`：对规范化轨迹做 SHA-256 前 16 位；规范化 = 事件顺序 + 类型 + 节点属性 + 动作 + 时间量化到 100ms + 屏幕摘要标签。用于 AI 计划绑定。
   - 警告列表：给界面显示，不阻止保存。

### 6.2 选择器合成

优先级：

1. `viewId` 非空且符合全写/短写规则 → `{ "id": "包名:id/名称" }`。
2. `text` 非空且不像动态文本 → `{ "text": "...", "className": "..." }`。
3. `desc` 非空 → `{ "desc": "...", "className": "..." }`。
4. 只有 class + bounds → `{ "className": "...", "minWidth": ..., "minHeight": ... }`；标红，要求用户确认后才能运行。
5. 都没有 → 不生成步骤，记 `unrecordable`，提示重录。

「像动态文本」启发式：长度 >40、含 4 位以上连续数字、含日期/时间模式、含 `%` 或货币符号。命中时优先 `textContains`（取前 12 个字符）并标低置信；不自动用 `textStartsWith`/`textEndsWith`。

### 6.3 时序

- `waitBeforeMs = clamp(上一步事件到本步事件的间隔, 0, 3000)`，按 50ms 取整。
- `timeoutMs = clamp(max(1500, 3 × 观察到的「动作→下一屏幕」延迟), 1500, 15000)`。
- `settleMs = 300`。
- 如果观察到的延迟缺失，`timeoutMs = defaults.timeoutMs`（5000）。

### 6.4 期望

按「动作后 2 秒内发生了什么」：

| 观察 | `expect` |
| --- | --- |
| 出现新的 `WINDOW_STATE_CHANGED` | `screenChanged` |
| 目标节点消失且界面变化 | `nodeGone`（带目标选择器） |
| 出现新的高置信文本 | `textAppears`（带文本） |
| 什么都没观察到 | `none` |

`none` 不阻止运行，但会在界面上标「未验证」。最终成功建议用户/AI 加一个 `assert` 节点。

### 6.5 可选与风险

**可选**（满足任一，标 `optional=true`，`onSkip` → 下一步）：

- 文字属于 {跳过, 关闭, 以后再说, 取消, 知道了, 我知道了, 允许, 暂不}。
- bounds 在屏幕顶部 25% 或底部 25%，且文字属于上述集合。
- 该步骤之后界面回到与之前相同的 `activity + digest`（弹窗关闭）。

**风险**（`risk=true`，`retries=0`）：

- 文字含 {支付, 确认支付, 付款, 转账, 发送, 提交, 删除, 卸载, 退出, 注销, 授权, 允许}。
- 文字含货币符号/金额模式。
- 风险步骤在运行前需要一次显式确认；V1 可在流程详情里勾选「本次运行跳过确认」，但不持久化。

> 可选/风险都是启发式，编译只给建议；用户可改，AI 可改（见 §7）。

### 6.6 AI 编导（2B）

**定位**：AI 只对录制素材做剪辑、标注、参数化与 guard；**不写选择器、不新增动作**（新增动作由 2A 开关控制）。

**输入**：轨迹（按 `sharingLevel` 脱敏）+ 本地草稿 + 校验器约束。

**输出**：编导计划（JSON），只含操作，不含完整工作流。

```json
{
  "schema": 1,
  "workflowId": "wf-5f2c1a9e",
  "baseRevision": 1,
  "traceHash": "8a1c0f2d7e4b9a63",
  "intent": {
    "name": "每日签到",
    "description": "打开签到页并领取每日奖励",
    "success": { "kind": "textVisible", "text": "签到成功", "evidence": { "step": 4, "label": "签到成功" } }
  },
  "operations": [
    { "op": "annotate", "step": 0, "optional": true, "reason": "开屏广告不一定出现" },
    { "op": "set_param", "step": 3, "timeoutMs": 8000, "reason": "实测切换耗时 4.2 秒" },
    { "op": "drop", "step": 7, "reason": "点击后界面无变化，疑似误点" },
    { "op": "guard", "beforeStep": 3, "predicate": { "kind": "textVisible", "text": "已签到" }, "onTrue": "end-skip", "reason": "已签到则跳过" }
  ]
}
```

**允许的操作（2B）**：

| op | 作用 | 约束 |
| --- | --- | --- |
| `annotate` | 改 `optional`/`risk` | 引用已录制步骤 |
| `set_param` | 改 `timeoutMs`/`retries`/`waitBeforeMs`/`settleMs` | 在范围内 |
| `set_expect` | 改期望 | 引用轨迹里出现过的文字/节点 |
| `drop` | 删除录制步骤 | 给原因；用户逐条确认 |
| `merge` | 合并相邻同类步骤 | 只允许相邻、同动作 |
| `set_name` / `set_description` | 改元数据 | 长度限制 |
| `set_success` | 设最终断言 | 必须引用轨迹里出现过的文字/节点 |
| `guard` | 在某个录制步骤前插入条件节点 | 谓词必须引用轨迹里出现过的文字/节点；`onTrue` 必填且只能指向已有节点或 `end`/`pause`；`onFalse` 固定指向原步骤 |

**2A 开关（默认关闭，实验功能）**：

- 开关粒度：每个工作流 `allowAiAddNodes=false`；只有用户在设置里显式打开「实验：允许 AI 新增动作节点」后，AI 才能提 `add_action`。
- `add_action` 必须引用轨迹里观察到的节点（`evidence.step`），动作类型只能是 click/longClick/scroll/setText/back/wait；不能是 launch；不能写坐标；`setText` 文本必须是参数（不能是 AI 编造的字面量）。
- 新增动作节点在 diff 里标「AI 新增」，默认不勾选，用户必须显式接受。
- 即使打开，AI 仍不能改包名、不能放宽安全闸门、不能开启总开关。

**拒绝条件**：

- `baseRevision` 或 `traceHash` 不匹配 → `AUTOMATION_WORKFLOW_REVISION_STALE`。
- 引用不存在的步骤/节点/标签 → `AUTOMATION_WORKFLOW_INVALID`。
- 计划应用后图不合法（环、不可达、缺边）→ 整体拒绝。
- 未知 op/字段、越界 → 整体拒绝。

### 6.7 计划应用与差异

- 计划不直接改活动 revision；应用后生成**候选 revision**。
- 差异按节点/边/字段展开：新增、删除、修改；每项带 `reason`、`source`、`riskLevel`。
- 用户逐条接受/拒绝；只有被接受的操作参与编译。拒绝全部即保持原 revision。
- 应用成功后 `revision+1`，`review` 记录 `planId`、`acceptedAt`、`acceptedOps`；原始轨迹不变。
- 「撤销 AI 修改」= 切回上一 revision，不删除轨迹。

### 6.8 确定性

- 同一轨迹 + 同一用户编辑 → 同一工作流 JSON（节点 id 按顺序分配，无随机、无当前时间参与）。
- `traceHash` 覆盖轨迹的全部语义字段（事件类型、节点属性、动作、顺序、时间量化到 100ms、屏幕摘要标签），不覆盖录制时间/展示用 id。轨迹一旦冻结就不可变，因此同一 hash 一定对应同一份可审阅素材；AI 计划绑定 hash，避免「审的是 A、应用到了 B」。
- AI 计划不参与运行时；只在编译期使用。

## 7. 执行

### 7.1 运行状态机

```text
IDLE
  → PREPARE（总开关 running、白名单、锁屏/敏感窗口、前台包/Activity）
  → NODE（当前节点）
      action:
        WAIT_TARGET（轮询目标，timeout）
        ACT（执行动作）
        VERIFY（等待 expect，timeout）
      condition: EVAL（立即）
      assert: WAIT（轮询谓词，timeout）
      end: DONE
      pause: INCIDENT
  → 下一个节点 …
  → DONE / PAUSED / CANCELLED
```

- 单槽位：同一时刻只允许一个运行；录制与运行互斥。
- `start.launch=true` 时，运行前先按既有 `mobile_device_app_launch` 口径启动目标包，再等前台包/Activity 匹配；`false` 时要求目标应用已经在前台。启动失败 → `AUTOMATION_WORKFLOW_TARGET_LEFT`（不猜别的入口）。
- 运行由服务主线程 + `Handler` 驱动；等待用轮询/事件唤醒，不阻塞主线程。
- 每步动作前重新取窗口、重跑白名单/锁屏/敏感窗口/频率判定；不缓存上一节点的节点句柄。
- 总超时 `totalTimeoutMs`（默认 90s，最大 10min）；超时 → 暂停 + `AUTOMATION_WORKFLOW_TIMEOUT`。
- 运行记录：只记节点 id、动作类型、结果码、耗时；不记文本、viewId、坐标、输入内容。

### 7.2 条件、断言与汇合

- `condition` 求值使用当前快照；如果当前没有可读窗口 → 暂停 `AUTOMATION_WORKFLOW_TARGET_LEFT`，不猜。
- `assert` 轮询间隔 200ms；`settleMs` 用「连续成立」判定。
- 汇合点不等待：先到的分支继续；另一分支不会被执行（单 token）。
- 条件分支如果指向 `pause`，该 `pause` 的现场单会记录来自哪个节点。

### 7.3 闸门

顺序（先拒绝者胜）：

1. 总开关 `AutomationControlPolicy.admits(runtime)`；不是 `running` → 拒绝运行/暂停。
2. 白名单 `AccessibilityAutomationStore.packageAllowed`。
3. 锁屏/熄屏 `isLockedOrScreenOff`。
4. 敏感窗口 `containsSensitiveWindow`（fail-closed）。
5. 前台包/Activity 与 `start` 一致；不一致 → `TARGET_LEFT`。
6. 动作频率 `ACTION_INTERVAL_MS = 350L`（所有动作共用）。
7. 节点级 `risk` 确认（如果开启）。

所有拒绝都写审计：`ACCESSIBILITY_ACTION` + 受控 detail；**不写包名、viewId、文本、输入内容**。

### 7.4 失败与现场单

| 场景 | 码 | 行为 |
| --- | --- | --- |
| 目标在 timeout 内没出现 | `AUTOMATION_WORKFLOW_TARGET_MISSING` | 可选 → 跳过；否则暂停 |
| 动作执行了但期望未达成 | `AUTOMATION_WORKFLOW_NOT_VERIFIED` | 暂停（风险节点不重试） |
| 断言超时 | `AUTOMATION_WORKFLOW_ASSERT_TIMEOUT` | 暂停 |
| 前台换了应用 | `AUTOMATION_WORKFLOW_TARGET_LEFT` | 暂停 |
| 锁屏/敏感页 | 复用 `ACCESSIBILITY_DEVICE_LOCKED` / `ACCESSIBILITY_SENSITIVE_WINDOW` | 暂停/中止，不交给 AI 绕 |
| 频率限制 | `ACCESSIBILITY_RATE_LIMITED` | 等待后重试该步一次；这次尝试计入节点 `retries` |
| 总超时 | `AUTOMATION_WORKFLOW_TIMEOUT` | 暂停 |
| 用户中止 | `AUTOMATION_WORKFLOW_CANCELLED` | 结束 |

现场单字段：

```json
{
  "runId": "run-...",
  "workflowId": "wf-...",
  "revision": 2,
  "nodeId": "n4",
  "code": "AUTOMATION_WORKFLOW_NOT_VERIFIED",
  "message": "第 4 步发出去了，但没有观察到「签到成功」",
  "elapsedMs": 8234,
  "attempts": 1,
  "path": ["n1", "n2", "n3", "n4"],
  "facts": {
    "packageName": "com.example.app",
    "activityName": "com.example.app/.CheckinActivity",
    "windowDigest": "…",
    "locked": false,
    "sensitive": false
  },
  "candidates": []
}
```

`candidates` 只在用户允许共享时附带最多 10 个可见节点摘要；默认空。

### 7.5 恢复 / 跳过 / 中止

- **重试**：从当前节点重新执行；重新取目标，不拿旧节点；受 `retries` 限制。
- **跳过**：仅对 `optional` 节点或用户显式选择「跳过这一步」可用；跳到 `onSkip` 目标。跳过会记 `skipped`，不记成功。
- **恢复**：用户/AI 处理完卡点后，从当前节点重新开始；必须重新校验前台包/Activity/指纹；不重放已成功节点。
- **中止**：结束运行，状态 `cancelled`；已执行的动作不回滚（自动化没有事务）。
- 恢复必须带 `runId` + `nodeId` + `revision`；不匹配 → `AUTOMATION_WORKFLOW_RESUME_INVALID`。

**运行模式**（不要把它们混成「试运行」一个词）：

| 模式 | 行为 | 能验证什么 |
| --- | --- | --- |
| `validate` | 纯静态：图校验 + 选择器对轨迹节点的接地检查；不连设备 | 模型/图/计划是否合法；不能证明真机可跑 |
| `dryRun` | 连设备但不执行动作：校验 `start` 前置 + 当前屏第一个动作的目标是否存在，然后停在「将执行」 | 第一屏是否就绪；不能验证后续步骤 |
| `step` | 真正执行，但每步后暂停等用户确认「继续/跳过/中止」 | 全流程；适合风险流程与首次验收 |
| `run` | 连续执行到结束/暂停 | 全流程；适合已验收流程 |

> `dryRun` 不会连续推进：不执行动作，界面就不会变，所以它**只能**回答「第一屏是否匹配」。不要在文案里说成「预演整个流程」。

### 7.6 Surface 抽象

```kotlin
internal interface WorkflowSurface {
    fun packageName(): String?
    fun activityName(): String?
    fun snapshot(): AutomationNode?
    fun digest(): String
    fun find(selector: Selector): WorkflowTarget?
    fun perform(node: WorkflowTarget?, action: AutomationAction, value: String?): BackendOutcome
}
```

- V1 实现 `MainScreenSurface`：`rootInActiveWindow` + `AndroidAutomationNodeBackend`。
- 以后 `DisplaySurface(displayId)`：复用 `displayRootFor(displayId)`、`displayWindowRoot`、文本写入链；流程级 `surface` 或节点级覆盖。
- V1 校验器拒绝 `surface != "main"`，但 schema/runner 已经按接口写，不把主屏假设散落到节点逻辑里。

## 8. AI 交互

### 8.1 现状约束

壳页（Capacitor WebView）与 Harness 宿主之间只有 `MobileRuntime` 桥，**没有会话端点**；loopback 有动态端口、HttpOnly 令牌、混合内容、无 REST 四道门（见 `docs/壳页会话列表接线调研.md`）。因此：

- V1 **不能**由 App 自动创建/注入一条「工作流设计会话」。
- V1 能做：流程页生成设计简报 → 打开 Harness → 用户新建对话并粘贴 → AI 通过工具读流程、提计划。
- 以后要自动建会话，需要新增桥方法 + 宿主 API；那是独立工程，不在本设计内。

### 8.2 设计会话

**目的**：让 AI 在一个专门的对话里处理某个流程的参数，不污染主对话，也不让 AI 直接改盘面。

**流程**：

1. 用户在流程详情点「用 AI 优化」。
2. App 生成简报（`flowId`、`revision`、`traceHash`、共享级别、schema 摘要、可用工具、约束）。
3. App 打开 Harness；用户新建对话，粘贴简报。
4. AI 调 `mobile_workflow_get` 读轨迹/草稿/校验错误。
5. AI 调 `mobile_workflow_propose` 提交计划。
6. App 收到计划，编译候选 revision + diff，显示「有建议」。
7. 用户在工作流视图逐条接受/拒绝。
8. 用户可回到同一对话继续迭代；AI 再调 `get` 读新 revision。

**运行时会话**：流程暂停后，现场单可生成一段运行时简报；用户开对话让 AI 处理。AI 先直接处置（现有单步工具），不行再提参数补丁，最后才建议中止。

### 8.3 工具与命令

**App UI ↔ 原生**（`MobileRuntimePlugin`，供设置页调用）：

- `listAutomationWorkflows(packageName?)`
- `getAutomationWorkflow({ id })`
- `saveAutomationWorkflow({ workflow })`（用户编辑）
- `deleteAutomationWorkflow({ id })`
- `startAutomationRecording({ packageName })`
- `stopAutomationRecording()`
- `getAutomationRecordingState()`
- `runAutomationWorkflow({ id, mode })`（`mode: "run" | "dryRun" | "step"`）
- `pauseAutomationWorkflow()`
- `resumeAutomationWorkflow({ nodeId })`
- `abortAutomationWorkflow()`
- `getAutomationWorkflowRun()`
- `listAutomationWorkflowProposals({ id })`
- `applyAutomationWorkflowProposal({ id, ops })`
- `rejectAutomationWorkflowProposal({ id })`
- `listAutomationWorkflowRevisions({ id })`
- `activateAutomationWorkflowRevision({ id, revision })`

**AI ↔ 原生**（`DeviceBridgeServer` 一条命令 `automationWorkflow`，`op` 区分）：

| op | 用途 | AI 可用 |
| --- | --- | --- |
| `list` | 列工作流元数据 | 是 |
| `get` | 读工作流 + 轨迹摘要（按共享级别） | 是 |
| `propose` | 提交编导计划 | 是 |
| `validate` | 校验候选图 | 是 |
| `history` | 读 revision 列表 | 是 |
| `status` | 读运行状态/现场单 | 是 |
| `resume` | 从暂停恢复 | 是（仅在已有暂停运行时） |
| `abort` | 中止运行 | 是 |
| `run` | 开始运行 | **否**（只能用户点） |
| `recordStart` | 开始录制 | **否**（隐私） |
| `save` / `delete` | 改盘面 | **否**（只能用户） |

**Node 插件工具**：`mobile_workflow_list`、`mobile_workflow_get`、`mobile_workflow_propose`、`mobile_workflow_validate`、`mobile_workflow_history`、`mobile_workflow_status`、`mobile_workflow_resume`、`mobile_workflow_abort`。工具描述里必须写清「不能开始运行、不能录制、不能改盘面、不能用坐标」。

### 8.4 提案与审批

- 计划只进 `proposals` 区，不改活动 revision。
- App 编译计划 → 候选 revision + diff；校验失败直接拒绝并回错误码。
- 用户逐条接受；接受的操作集重新编译（不是把整份候选直接保存），保证拒绝某项后图仍合法。
- 操作应用时必须保持图合法：`drop` 把前驱重连到被删节点的 `onSuccess`；`merge` 合并相邻同类节点的边；`guard` 插入条件节点，`onFalse` 指向原步骤、`onTrue` 指向指定目标（默认 `end`）；任一重连产生歧义或环，整份计划拒绝。
- App 不轮询模型：提案落盘后，流程列表/详情在下次打开或手动刷新时显示「有建议」；AI 的工具回执里提示用户回 App 确认。
- 应用成功后写 `review` 元数据与审计（只记 `planId`、操作数、结果，不记界面文本）。
- 提案有 TTL（例如 24h）与 `baseRevision`；过期/过期 revision 拒绝。

### 8.5 运行时兜底优先级

用户确认的顺序：

1. **直接处置**（优先）：AI 用现有单步设备工具（`mobile_accessibility_action` / `tap` / `input_text` / `back`）清掉卡点（关弹窗、返回、重新进入页面），然后 `resume`。不改工作流。
2. **改参数**（其次）：直接处置无效时，AI 提计划改选择器/超时/可选/期望；用户确认后应用，再 `resume`。
3. **中止**：无法安全继续时 `abort`。

约束：

- 每次运行最多 3 次 AI 干预 / 2 分钟；超过自动转人工。
- 风险节点、敏感窗口、锁屏：直接中止，不交给 AI 绕。
- 所有 AI 动作走现有闸门与审计；AI 不能开总开关、不能改白名单、不能写坐标。
- AI 的 `resume` 必须引用当前暂停的 `runId`/`nodeId`；不能恢复一个已结束/已取消的运行。

## 9. 用户界面

### 9.1 流程列表

位置：设置 → 自动化 → 目标应用 → 「工作流」。每行显示：

- 名称、步数、最近一次运行结果（成功/暂停/中止）、最后更新时间、活动 revision。
- 状态徽标：`草稿` / `AI 有建议` / `有分支` / `含风险步骤` / `需要确认的选择器`。
- 操作：运行、编辑、更多（复制、导出、删除、查看轨迹）。

### 9.2 工作流视图

- 纵向节点卡片 + 连线；`condition` 用菱形/分叉卡片；`optional` 用虚线跳过边；失败边红色指向 `pause`。
- 当前运行节点高亮；已走路径打勾；暂停节点显示现场单入口。
- 节点卡片显示：动作、目标摘要（viewId/文字，不展开长文本）、期望、超时/重试徽标、`可选`/`风险`/`AI 新增` 徽标。
- 点节点 → 右侧/底部参数面板（9.3）。
- 图只读；编辑通过参数面板与「插入」菜单，不做自由拖拽连线（V1）。这样避免图编辑器的复杂手势与误连。

### 9.3 结构化编辑器

- 节点列表 + 图视图切换；同一份数据。
- 每个节点可改：动作、选择器（1..3，逐条编辑）、输入值模式、等待/超时/重试/`settleMs`、`optional`、`risk`、期望。
- 出边用下拉：`成功 →`、`失败 →`、`跳过 →`、`真 →`、`假 →`；下拉只列合法目标，实时校验。
- 「插入」菜单：条件、断言、等待、返回、结束、暂停。
- 「恢复录制值」：把该节点恢复为编译时的值（如果有 `provenance.traceStep`）。
- 校验错误就地显示；保存前必须通过校验。

### 9.4 运行视图

- 运行前确认：目标应用、步数、风险步骤数、是否 `dryRun`/`step`。
- 运行中：当前节点、已用时、已完成步数；「暂停」「中止」。
- 暂停：现场单卡片，展示失败码、节点、原因、路径；按钮：重试、跳过（仅可选）、中止、让 AI 处理（生成运行时简报）。
- 结束：成功/失败/取消；显示路径与耗时；「再跑一次」。

### 9.5 版本与差异

- revision 列表：原始录制、AI 建议、用户编辑；显示时间、来源、操作数。
- 差异：图视图上标绿（新增）/灰（删除）/黄（修改）；列表逐项显示原因。
- 接受/拒绝；接受后生成新 revision；可切回旧 revision（运行只认活动 revision）。
- 「删除原始轨迹」独立于 revision；删除后 AI 无法再基于轨迹提计划，但现有工作流仍可运行。

### 9.6 录制入口

- 应用选择器（复用现有 `ApplicationPicker`）→「开始录制」。
- 倒计时覆盖层/通知；录制中通知常驻；停止后自动打开预览。
- 浏览器预览（无设备）显示「浏览器预览不能录制」；不伪造流程。

## 11. 存储

### 11.1 文件与键

- 独立偏好文件 `accessibility_automation_workflows`（与白名单、密码、规则隔离）【推】。
- 键：
  - `index`：JSON 数组 `[{id, packageName, name, revision, updatedAt}]`，便于列表读取；不用 `\t`/`\n` 拼接，避免名称里的分隔符破坏索引。
  - `wf:<id>`：活动工作流 JSON。
  - `hist:<id>`：最近 5 个 revision 的 JSON 数组（或分键 `rev:<id>:<n>`）。
  - `trace:<id>`：轨迹 JSON；用户可删。
  - `prop:<id>`：未处理的提案 JSON（可多条，最多 3 条）。
- 写入：先构造完整 JSON，再一次 `put` + `commit()`；不做「先删后写」。
- 读取：索引坏了 → 重建扫描 `wf:` 键；单条坏了 → 返回 `Corrupt`，**不自动删除**（用户数据，保留导出/删除入口）。

### 11.2 限额

| 项 | 上限 |
| --- | --- |
| 每个包工作流数 | 20 |
| 全局工作流数 | 50 |
| 节点数 | 40 |
| 边数 | 80 |
| 单工作流 JSON | 128 KiB（UTF-8） |
| 单轨迹 JSON | 256 KiB |
| 每流程提案 | 3 |
| 每流程 revision | 5 |
| 节点选择器 | 3 |
| 字符串字段 | 200 字符（沿用 `AutomationRuleLimits`） |

超限是**拒绝**，不截断；提示具体项。

### 11.3 损坏与迁移

- `schema` 版本号；未知版本按「不支持」返回，不尝试猜测。
- 未知字段、类型不符、越界：整体拒绝（与 `AutomationRule` 一致）。
- 损坏的单条工作流：列表里显示「损坏」，提供导出/删除；不参与运行。
- 轨迹缺失但工作流存在：可运行；AI 审阅不可用。
- 未来字段升级：新增字段必须在旧版本被忽略还是拒绝？按现有严格口径**拒绝**；升级时做迁移或保留旧版本读取器。

### 11.4 与现有偏好的关系

- 不改 `accessibility_automation_rules`、`accessibility_automation_app_config`、`accessibility_automation_control`。
- 工作流的「按应用暂停」是否复用 `AccessibilityAppConfigStore.paused`？**建议复用**：用户暂停某个应用时，规则与工作流都停。暂停只挡运行与规则求值，**不挡录制**（录制是只读的）。文档记录这一耦合。

### 13.3 真机【验】

- 事件覆盖：微信/浏览器/Flutter/WebView/系统设置；`TYPE_VIEW_CLICKED` 是否派发；`event.source` 是否为空。
- 录制 → 编译 → 回放 5 步流程，连续 3 次；广告弹窗出现/不出现两种路径。
- 条件分支：已签到/未签到两条路径。
- 选择器稳定性：应用升级后 viewId 是否变化；文本变化是否导致失败。
- 时序：慢网/动画下超时是否合理；`settleMs` 是否能避免误判。
- 安全：支付/验证码页强制拒绝；锁屏；非白名单；频率限制。
- 服务断开/重连：运行暂停、录制停止、恢复行为。
- 通知/悬浮球：录制中可见、停止可达。

### 13.4 安全回归

- AI 不能 `run`/`recordStart`/`save`/`delete`。
- AI 计划不能改包名、不能写坐标、不能加 launch、不能放宽闸门。
- 2A 关闭时新增动作节点被拒；打开后新增动作节点仍需用户勾选。
- 所有拒绝/运行都写审计，detail 只有受控码，不含文本/viewId/包名。
- 现场单默认不带文本；共享级别为 `none` 时 `candidates=[]`。

## 15. 风险与开放问题

### 15.1 风险

1. **事件覆盖不足**：WebView/Flutter/游戏可能录不到点击；V1 只能提示「这个界面录不了」，不能假装成功。
2. **条件分支让用户更难理解**：默认只显示线性主链；只有存在分支时展开；图视图只读、编辑用结构化控件。
3. **无循环**：「滚动直到找到」「重复直到成功」V1 表达不了；如实说明，后续再加 `loop` 节点。
4. **AI 计划质量**：可能删错步骤、起错名字、设错成功判据；diff 评审是必需环节，不能自动应用结构变更。
5. **隐私**：轨迹含屏幕文字；默认 `labels`，发送前预览；输入内容不存；密码/敏感页不采集。
6. **时序常数**：1500/5000/15000ms 都是起点，需要真机调；不要把它们写死成「结论」。
7. **图编辑器复杂度**：V1 不做自由拖拽连线，避免误连；用结构化下拉 + 插入模板。
8. **与规则系统重复**：两套模型并存，用户可能困惑；文档与界面要写清「规则=事件触发单步，工作流=按需多步」。
9. **AI 会话**：V1 不能自动建会话；用户要手动开对话、粘贴简报；这是已知摩擦，不是 bug。
10. **失败不可回滚**：已点击/已发送的动作不会因为后面失败而撤销；现场单与「不自动重试风险步骤」是唯一保护。

### 15.2 开放问题（需要用户拍板）

| # | 问题 | 建议 |
| --- | --- | --- |
| 1 | 输入内容是否允许存字面量？ | V1 默认不存；要自动填就让用户显式改 `literal`，本地保存、不共享给 AI。 |
| 2 | AI 运行时能否自动应用「安全数值补丁」（超时/重试）？ | 默认必须用户确认；可在流程级加「允许 AI 自动调数值」开关，默认关。 |
| 3 | 是否复用 `AccessibilityAppConfigStore.paused` 同时暂停规则与工作流？ | 建议复用，语义一致（用户暂停这个应用）。 |
| 4 | 工作流是否也要支持事件触发（如打开应用就运行）？ | V1 只手动；触发是下一层，先不混进模型。 |
| 5 | 是否把 `AutomationTaskLedger` 合并进工作流运行器？ | V1 不合并；台账继续服务 AI 单步任务，工作流用独立运行器。 |
| 6 | 图编辑器是否要自由拖拽？ | V1 不做；结构化编辑 + 只读图视图。 |
| 7 | 是否允许 AI 新增动作节点（2A）在 V1 就默认开？ | 默认关；实验开关，逐条确认。 |
| 8 | 保存字面量时是否加密？ | V1 依赖应用私有目录；不引额外加密，避免密钥管理复杂度；文档写明边界。 |

## 16. 附录：关键交互示例

### 16.1 录制 → 草稿

轨迹（简化）：

```json
[
  { "type": "click", "node": { "text": "跳过", "viewId": "com.example.app:id/skip", "clickable": true }, "atMs": 800 },
  { "type": "click", "node": { "text": "我的", "viewId": "com.example.app:id/tab_me", "clickable": true }, "atMs": 4200 },
  { "type": "click", "node": { "text": "签到", "viewId": "com.example.app:id/checkin_entry", "clickable": true }, "atMs": 6100 },
  { "type": "click", "node": { "text": "签到", "viewId": "com.example.app:id/checkin_button", "clickable": true }, "atMs": 7600 },
  { "type": "window", "activity": "com.example.app/.CheckinActivity", "atMs": 7900 },
  { "type": "text", "text": "签到成功", "atMs": 8200 }
]
```

草稿：

```text
start
  → n1 点击「跳过」 [optional, skip→n2]  (id .../skip)
  → n2 点击「我的」                     (id .../tab_me)
  → n3 点击「签到」                     (id .../checkin_entry)
  → n4 点击「签到」  expect=screenChanged (id .../checkin_button)
  → n5 assert 文字「签到成功」           (来自屏幕摘要)
  → end-ok
失败 → pause
```

### 16.2 AI 编导（2B）

AI 计划：

```json
{
  "baseRevision": 1,
  "traceHash": "8a1c0f2d7e4b9a63",
  "intent": { "name": "每日签到", "success": { "kind": "textVisible", "text": "签到成功", "evidence": { "step": 5 } } },
  "operations": [
    { "op": "annotate", "step": 0, "optional": true, "reason": "开屏广告" },
    { "op": "set_param", "step": 3, "timeoutMs": 8000, "reason": "页面切换较慢" },
    { "op": "guard", "beforeStep": 2, "predicate": { "kind": "textVisible", "text": "已签到" }, "onTrue": "end-skip", "reason": "已签到则跳过" }
  ]
}
```

应用后：

```text
start
  → condition 「已签到」? ─是→ end-skip
  │否
  → n1 点击「跳过」 optional
  → n2 点击「我的」
  → n3 点击「签到」 timeout=8000
  → n4 点击「签到」
  → n5 assert「签到成功」
  → end-ok
失败 → pause
```

### 16.3 运行时兜底

1. 第 4 步 `NOT_VERIFIED`，流程暂停。
2. 用户打开对话，粘贴运行时简报。
3. AI 读 `status`，发现是「签到成功」文案变了；先用 `mobile_accessibility_action` 读树确认新文案（直接处置）。
4. 如果能继续：`resume`；如果不行：`propose` 改断言，用户确认后 `resume`。
5. 如果页面是支付/验证码：AI 直接建议 `abort`，不绕。
