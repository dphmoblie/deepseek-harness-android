# 主题色全局适配报告

面向用户诉求「主题卡片记得适配全局，之前设置分类的卡片和副屏都没有主题色」的改动记录与验证结果。

## 0. 摘要

- **只复用既有主题机制**（Web：`data-theme` / `data-accent` / 根元素上的 `--card-*`；Android：`AppThemePreference` + `res/values{,-night}/colors.xml`），没有新造第二套配色体系，没有新增任何依赖。
- 用户点名的三处都跟上了主题：
  1. **设置页分类芯片**（`.settings-categories button`）与同页卡片共用一套 `--card-*` 卡片令牌；
  2. **副屏页面**（`VirtualScreenActivity`）在 `attachBaseContext` 覆写 `uiMode` —— 这是「副屏不跟主题」的**根因**，控件默认样式此前按**系统**深浅解析；
  3. **副屏悬浮面板**（`VirtualScreenService.showOverlay()`）与**无障碍确认浮层**（`DeepSeekAccessibilityService.showConfirmation()`）里写死的底色/文字色全部改成 `overlay_panel_*` 令牌。
- 全局扫描后，`src/styles.css` 令牌块之外的 4 处颜色字面量收进新令牌 `--bg-scrim` / `--shadow-color`；`src/**` 与 `app/src/main/java/**` 里不再有「该跟主题却没跟」的硬编码颜色（保留项见 §4）。
- 验证：`vitest` 33 文件 451 用例 → **35 文件 470 用例全绿**；`tsc --noEmit` 0 error；`eslint .` exit 0；`gradle :app:assembleRelease` **BUILD SUCCESSFUL**；`gradle :app:lintRelease` **3 Error，全部来自并发任务尚未提交的新代码**（证据与行内修法见 §6），本次改动引入 0 条新 lint 问题。

## 3. 关键设计点（为什么这么改）

- **`palette()` 而不是新主题**：`values/`-`values-night/` 只认系统深浅，应用主题是应用自己存的。复制 `Configuration` 只改 `uiMode` 再 `createConfigurationContext`，就能让 `getColor(R.color.*)` 与 AppCompat 控件默认样式都按**用户选的**主题解析。这个模式仓库里本来就有先例（`HarnessActivity.kt:67-68` 用 `attachBaseContext(AppLanguage.localizedContext(newBase))`），所以它是推广而不是新机制。
- **Activity 在 `attachBaseContext` 改，Service 用 `ContextThemeWrapper(…, R.style.AppTheme)`**：Service 没有主题入口，直接 `new Button(this)` 会按系统深浅解析 AppCompat 默认样式；`ContextThemeWrapper` + `R.style.AppTheme` 是 `OverlayBallService.kt:295` 已经在用的既有做法（那里的注释记录了「厂商强制深色会让 inflate 抛 UnsupportedOperationException 而直接闪退」的教训）。
- **`color-mix()` 必须给兜底值**：`var(--card-color)` 未定义时整条声明在计算值阶段失效，卡片底色会掉成透明。所以新写的规则一律 `var(--card-*, 主题基础值)`。
- **深浅两套都要看得清**：新令牌都成对定义（`#667181` / `#9DABBB` 都是 Web `--muted` 的原值），遮罩在深色下从 20% 提到 32%、阴影在深色下改 `rgb(0 0 0 / 45%)`，因为原 4%~5% 的浅影子在深色底上根本看不见。
