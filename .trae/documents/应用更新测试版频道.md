# 版本管理：应用更新「测试版频道」

## Context（背景）

版本管理页的「应用更新」目前**没有频道概念**：`AppReleaseCatalog` 从 GitHub 发布页挑选「严格更新」时，只要版本号更大就纳入候选——正式版用户（如装着 `0.2.13`）也会被推送更高版本的测试构建（`0.2.14-mobile-1`）。用户无法选择只收正式版，也无法显式加入测试。

本次改动在版本管理页增加「接收测试版本」开关：

- **范围仅应用自身 APK 更新**（不含运行时 rootfs 更新）。
- **默认正式版频道（stable）**：只接收正式版更新；这是对现有行为的变更——开关出现后，正式版用户默认不再被 `-mobile-N` 测试构建打扰。
- **测试版频道（beta）**：手动开启后，更新检查把测试构建纳入候选，自动取最新（行为与现状一致）。
- **已装测试构建的用户任何时候都能收到同版本正式版**（沿用现有收敛路径，不受频道影响）。

## 关键设计决策

1. **频道持久化在原生 SharedPreferences（`dsh-app-update-channel`），前端不存、不传参**。
   - 与 [MobileRuntimePlugin.kt](file:///d:/data/project/deepseekharness/app/android/app/src/main/java/io/deepseekharness/mobile/MobileRuntimePlugin.kt) L640「频道与地址由原生自己决定，前端不能传任意 URL」的安全边界一致：频道决定下载哪个 APK，属同一决策面。
   - `downloadAppUpdate` 内部 `requireAppUpdate()`（L745）会重算候选；频道在原生侧时，「界面显示的候选」与「实际下载的包」天然同源，无竞态。
   - `getAppUpdateState` 的三处前端调用方（版本管理页、每日提醒 hook、提醒去重）零改动自动生效。
2. **过滤点放在 `availableRelease` 遍历循环内**：`stable` 频道跳过一切 `suffix != 0` 的构建；私有 `isUpdateOf` 收敛逻辑不改——装了测试构建的用户切回 stable 后仍收同版本正式版与更高正式版，但不收任何测试构建。
3. **缓存按频道失效**：channel 存入 `AppUpdateCache.Snapshot`，`usable()` 增加比对，schema 1→2（旧缓存一次性作废重查）；`inFlight` 键改为 `(installed, channel)`，两频道并发查询不共享请求。
4. **桥接 API**：`getAppUpdateState` 响应新增必填 `channel` 字段；新增 `setAppUpdateChannel(channel)` 写 prefs 后以 `forceRefresh=true` 重查并返回完整最新 state（一次往返）；`downloadAppUpdate`/`installAppUpdate` 签名不变。
5. **每日提醒零改动**：`appUpdateReminder.ts` 走 `getAppUpdateState`，原生自动按频道过滤。接受边界：当天已按 stable 标记「已检查」后切 beta，当天不再自动提醒，次日生效。

## 分文件改动

### Kotlin（3 个文件）

**1. [AppReleaseCatalog.kt](file:///d:/data/project/deepseekharness/app/android/app/src/main/java/io/deepseekharness/mobile/runtime/AppReleaseCatalog.kt)**
- 文件内新增 `internal enum class AppUpdateChannel(val id: String) { STABLE("stable"), BETA("beta") }`，伴生：`DEFAULT = STABLE`、`fromId(String?)`（非法返回 null）、`load(context)`（读坏/读不到回 STABLE，`catch (Throwable)` 兜底——项目硬约束）、`save(context, channel)`；prefs 常量 `PREFS_NAME = "dsh-app-update-channel"`、`KEY_CHANNEL = "channel"`。
- `availableRelease(installed, channel: AppUpdateChannel)`：循环内 `isUpdateOf` 之前加 `if (channel == AppUpdateChannel.STABLE && version.suffix != 0L) continue`。**不给默认参数**，强制每个调用点显式决策。
- 更新 `isUpdateOf` 上方 KDoc，说明 stable 过滤与既有「正式版拒同版本测试包」规则的关系（后者保留，与频道正交）。

**2. [AppUpdateCache.kt](file:///d:/data/project/deepseekharness/app/android/app/src/main/java/io/deepseekharness/mobile/runtime/AppUpdateCache.kt)**
- `Snapshot` 加 `channel: AppUpdateChannel`；新增 `LookupKey(installed, channel)` 作为 `inFlight` 键。
- `state(installed, installAllowed, channel, forceRefresh)`：返回 JSON 统一 `.put("channel", channel.id)`（与 `cached`/`checkedAt` 同处）。
- `availableRelease(installed, channel)`；`lookup` 全程带 channel；`usable()` 首行加 `snapshot.channel != channel` 比对。
- schema 常量 1→2；`encode` 写 channel；`decode` 对 `schema != 2` 或 channel 缺失/非法整份拒绝（fail-closed，沿用现有腐化处理风格）。

**3. [MobileRuntimePlugin.kt](file:///d:/data/project/deepseekharness/app/android/app/src/main/java/io/deepseekharness/mobile/MobileRuntimePlugin.kt)**
- `getAppUpdateState`（L621）：`state(...)` 追加 `AppUpdateChannel.load(context)`；KDoc 补 channel 字段说明。
- 新增 `@PluginMethod setAppUpdateChannel`：`fromId(call.data.opt("channel") as? String) ?: throw RuntimeFailure("APP_UPDATE_INPUT_INVALID", "更新频道参数无效")`；`save` 后走 `AppUpdateCache...state(installed, installAllowed, channel, forceRefresh = true)` 返回。复用 `execute(call)`/`audited` 包裹（全局异常兜底已内建）。
- `requireAppUpdate()`（L745）：改传 `availableRelease(installed, AppUpdateChannel.load(context))`。
