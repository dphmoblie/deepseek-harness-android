# Git 提交与更新推送规范

在该仓库进行任何代码改动、版本发布、Git 提交（git commit）及推送（git push）时，必须严格遵守以下规范：

## 1. 语言规范
- **必须使用简体中文**：所有 commit message、PR 标题及正文、分支推送说明、Release Notes 和文档更新说明，严禁使用纯英文或中英混杂的不规范表述。
- 描述应当清晰明确，指出改动的**背景**、**原因**和**影响范围**，严禁使用如 `update`、`fix bug`、`modify` 等模糊字眼。

## 2. 提交信息（Commit Message）格式
遵循约定式提交（Conventional Commits）规范，格式如下：

```
<类型>(<影响范围可选>): <简短中文概述>

[可选详细说明，按条列出改动点]
- 改动点 1
- 改动点 2

[可选关联工单/需求编号]
```

### 常用类型定义：
- `feat`: 新增功能或需求实现
- `fix`: 缺陷与漏洞修复
- `docs`: 文档编写与更新（如需求设计、发布说明等）
- `style`: 代码格式化、标点与排版调整（不影响业务逻辑）
- `refactor`: 代码重构（既不修改功能也不修复 bug）
- `perf`: 性能、内存或渲染帧率优化
- `test`: 单元测试、集成测试补充与修复
- `chore`: 构建配置、依赖库升级、辅助脚本等基础工程变动

## 3. 发布更新说明（Release Notes）
- 依据仓库流水线规范，每次版本发布时应在 `docs/发布说明-<版本号>.md` 中维护对应版本的中文发布日志。
- CI 构建流程会自动读取该文件作为 GitHub Release 的发布正文。
